# 方案 41：断开→重连缩略图方向缺陷（rotation 脏缓存）修复

> **状态**：已实施（2026-10-10，9226aaf）。TDD 三用例（断开清缓存 /
> 连接清缓存 / 失败缓存→断开→重连→截图补偿行为级回归）全绿；
> 门禁 pytest 913 通过 + ruff + mypy strict。待用户浏览器复核
> .24 断开→扫描→缩略图链路。
> **背景**：方案 40 浏览器验收中用户发现——.24 设备「扫描并连接」后
> 缩略图方向颠倒，「刷新」后方向正确。视频流与截图按钮均正常。

## 一、现象

| 场景 | 结果 |
|------|------|
| .24 扫描并连接后缩略图 | 方向颠倒（错误） |
| 刷新缩略图（约 30s 后） | 方向正确 |
| 视频流 / 截图按钮 | 始终正确（方案 40 A 前端抓帧，不经 rotation 判据） |

## 二、根因分析（后端日志证据链，2026-10-10 16:15）

时间线（后端结构化日志，UTC+8 换算）：

1. `16:15:19-20` 用户批量断开 .13/.16/.18/.19/.24/.25 六台设备；
2. **断开毫秒级竞态**：缩略图自动加载的在途 screenshot 请求尚未完成——
   screencap 刚返回、get_rotation 的 `dumpsys display` 执行时设备已断，
   `returncode 255` → AdbError → 防御路径「失败收敛 0 并缓存 30s」
   （方案 38 B3）把 **rotation=0 写入 `_rotation_cache`**；
   - 日志原文：`.24 adb_command_failed(returncode 255)` →
     `get_rotation_failed` 于 `08:15:20.336Z`；
3. `16:15:29` 用户扫描 .10-.50 并自动连接（含 .24）；`16:15:31.5` .24
   tcp_connected；
4. 扫描完成后前端 `loadThumbnails(okIds)` 立即截图 .24——get_rotation
   **命中 TTL 内的脏缓存 0**（08:15:20 + 30s = 08:15:50 前均为 0）→
   无补偿 → 物理帧颠倒（.24 是舰队唯一 rotation=2 设备）→ 缩略图颠倒；
5. 用户刷新时已过 TTL → 真查 dumpsys display → mCurrentOrientation=2 →
   ROTATE_180 补偿 → 方向正确。

**根因定性**：`_rotation_cache` 以 device_id 为键、成败同缓存 30s
（方案 38 B3 防御设计），但**缓存没有随连接生命周期清理**——断开瞬间
的失败收敛值（0）被「断开 → 立即重连」的新生命周期继承。同一键、
新连接、旧状态，即在途请求的最后一口气污染了下一个连接的头 30 秒。

旁证：`disconnect_tcp` 已有 `_info_cooldown`/`_info_tasks` 清理
（方案 35 D4「防止断开后残留冷却/任务占用内存」）——同类缺口已有
先例可循，`_rotation_cache` 是该模式的遗漏项。

## 三、修复设计

**两处清理 + 行为级测试，改动仅 device_service.py**：

1. `disconnect_tcp`：与既有 cooldown 清理并列，加
   `self._rotation_cache.pop(device_id, None)`——生命周期结束即清；
2. `connect_tcp` 成功路径：加同款 pop——新连接首次截图必真查。双保险
   覆盖「未经过 disconnect 的生命周期切换」（设备掉线→自动恢复、
   直连后断连等），且语义直观：rotation 判据属于连接生命周期。

**不改**：方案 38 B3 的「成败同缓存 30s」防御（截图模式逐帧防
dumpsys 风暴，spike 验证过掉线期行为）；前端链路零改动。

## 四、测试计划（TDD，tests/unit + tests/application）

1. 应用层单测：seed `_rotation_cache[dev] = (0, now)` 模拟断开竞态 →
   `disconnect_tcp(ip, port)` → 断言缓存条目已清（后续截图将真查）；
2. 应用层单测：seed 脏值 → `connect_tcp` 成功 → 断言缓存已清；
3. 行为级回归（可选）：mock adb.get_rotation 序列 [异常→2]，
   「失败缓存 0 → disconnect → connect → screenshot」链路断言最终
   走 ROTATE_180 补偿（直接锚定用户场景）。

**门禁**：pytest `--cov-fail-under=80` + ruff（backend/app + 改动测试
