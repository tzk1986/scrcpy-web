## 三、T1（P0）逐项设计

### E2 — 上传文件名反斜杠路径穿越（安全，high）
- **位置**：`backend/app/application/file_service.py:84-89(_check_name), 218-226(upload)`
- **根因**：Windows 上 `tmp / name` 的 Path 拼接把 `\` 当分隔符；`posixpath.basename` 只拦 `/`；`_check_name` 现仅拒 `/`。
- **改法**：① `_check_name` 增加 `"\\" in name` 拒绝（400 invalid filename）；② upload 落盘前防御复核：`target = (tmp / name).resolve()`，校验 `tmp.resolve() in target.parents or target.parent == tmp.resolve()`，不满足抛 ValueError→400（纵深防御，即使校验面将来再漏也不逃逸）。
- **功能影响**：合法文件名不含 `\`（Windows 文件系统本身禁止），真实用户零影响；攻击性/畸形上传从「静默写到目录外」变 400。
- **风险/回归**：低。回归点：正常上传、含中文/空格名上传仍成功。
- **测试**：`tests/application/` 上传名含 `..\evil`、`a\b.txt` → 400；正常名 → 成功且落点在 tmp 内。

### E1 — 录屏 stop 进行态再入炸产物（high）
- **位置**：`recording_service.py:170-175`（仅拦终态）+ `cli.py:1313-1314`（首跑 pop 后二次返回 ""）
- **改法**：stop() 入口守卫扩展——会话状态为 `stopping/pulling`（非 recording 非终态）时**幂等直接返回当前会话**，不再调 cli.stop_recording、不 rm、不置 FAILED。仅 `recording` 态才走停止+拉取流程。
- **功能影响**：双击/并发 stop 从「后到者 rm 产物置 FAILED」变「后到者拿到进行态回执」；前端停止按钮连击不再可能白录。单执行流语义与方案 42 五态机一致。
- **风险/回归**：低。回归点：正常单次 stop 全流程（recording→stopping→pulling→done）不变；终态幂等返回不变。
- **测试**：STOPPING 态二次 stop → adb 桩零调用、状态保持、返回会话快照；recording 态 stop 正常推进。

### E5 — 自愈滞留判定基准漂移（high 邻域，medium）
- **位置**：`recording_service.py:387-400`（cutoff 比 `started_at`）+ `domain/recording.py`（RecordingSession）
- **根因**：stopping/pulling 滞留阈值 `time_limit+120s` 从「录制起点」折算，录满且 pull 慢（大文件/慢链路 >120s）的会话会被巡检 rm 正在拉取的设备端文件并置 FAILED。
- **改法**：`RecordingSession` 增 `phase_started_at: float = 0.0`；stop() 置 STOPPING、拉取置 PULLING 两处写入 `time.time()`；`_self_heal` 比较 `s.phase_started_at or s.started_at`（兜旧数据/未迁移形态）。实施时确认该 dataclass 是否入 SQLite 序列化面：若落库需同步 repo 映射与列默认值（仅内存则无迁移）。
- **功能影响**：慢 pull 不再被误杀；真正卡死（进入进行态后无推进 >120s）仍按原语义清理。用户可感知变化仅出现在「录满+慢网络」场景：产物从丢失变为完整拉回。
- **风险/回归**：中低。回归点：早停会话（录 10s 即停）自愈窗口按 phase 基准计算不缩短清理时效。
- **测试**：phase_started_at 新鲜（刚进 pulling）不被清理；phase_started_at 超窗被清理+rm_remote；started_at 有值 phase_started_at 为 0 的旧形态回退原判定。

### A01 — adb 截图无超时挂死（high）
- **位置**：`backend/app/infrastructure/adb/cli.py:1006-1013(screenshot), 1044-1051(screenshot_raw_gzip)`
- **改法**：两处 `await proc.communicate()` 包 `asyncio.wait_for(..., timeout=30)`（与 :372-376 注释口径一致）；TimeoutError 分支 `proc.kill(); await proc.wait()` 后抛 `AdbError("screenshot timeout")`。
- **功能影响**：设备/adb 卡死时截图请求从无限挂起变 30s 报错（HTTP 500/502 + 前端 F1-05 同步补 ElMessage.error 提示）。慢而活的截图被 30s 截断——现网 p95 « 30s，接受。
- **风险/回归**：低。回归点：正常截图耗时路径与返回值不变；kill 后不留僵尸进程。
- **测试**：桩 subprocess 永不返回 → 抛 AdbError 且 proc.kill 被调；正常输出 → 原样返回。

### C1 — 调试会话 idle reaper 缺位致槽位死锁（high）
- **位置**：`debug_service.py:786-812(_cleanup_loop 仅清 DB)`；规格：方案 05 Step 5（:306-337）
- **改法**：`_cleanup_loop` 每轮（现有 cleanup_interval_hours≈1h）扫描内存 `self.sessions`：`now - s.last_active > _SESSION_IDLE_TTL` 且**该会话当前无 WS 订阅者** → `await close_session(sid)` + `logger.info("session_cleaned", session=sid)`。新增模块常量 `_SESSION_IDLE_TTL_SECONDS = 3600`（**拍板项**，默认 1h；方案 05 伪码未定数值，确认后回填方案 05 文本）。close_session 现有实现已负责采集/shell 子进程与转发任务清理，直接复用。
- **功能影响**：打开后未显式 DELETE 的逃逸会话 1h 自动回收，解除 A1-L2 32 上限死锁；活跃会话因 logcat 收帧/exec/subscribe 均有 touch() 打点不受影响。**仍在订阅中的会话即使 last_active 过期也不回收**（保守侧）。
- **风险/回归**：中低——TTL 取值过短会误清低频使用者（3600s 兼顾）；回收须连带释放 `subscribers`/`shell_sessions` 侧效应（close_session 已有）。回归点：恢复（restore_sessions）路径与新回收互不干扰。
- **测试**：过期无订阅 → close；过期有订阅 → 保留；未过期 → 保留；回收后 33 连建不再 503。

### F1-01 — 回退态点重连永久黑屏（high，前端）
- **位置**：`frontend/src/services/h264VideoStream.ts:281-332(start)/365-382(suspend)` + `VideoPlayer.vue:526-527(reconnect)`
- **根因**：suspend() 置 `_suspended=true` 且 `_state='stopped'` 可过 start() 守卫，但 start() 不清 `_suspended` → 回退态 reconnect 后 `handleBinaryFrame` 只计数不解码，黑屏至刷新。
- **改法**：`start()` 开头复位 `this._suspended = false`（显式 start = 用户意图恢复，与 stop() 的清零语义对齐）；不动 reconnect() 与 watchdog。
- **功能影响**：截图回退态点「重连」恢复 h264 出帧（原黑屏）。页面隐藏等外部 suspend 场景不经 start()，暂停语义不变。
- **风险/回归**：低。回归点：正常首连 start、stop→start、suspend→resume 三条时序行为均不回退。
- **测试**：`.test.ts`——suspend 后 start，断言 `_suspended===false` 且后续二进制帧进解码路径。
