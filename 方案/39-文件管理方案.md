## 一、背景与目标

**用户意图**：为车队设备运维/调试场景提供设备文件管理能力，补齐
「文件进不去、日志拿不出」的调试闭环短板。

**成功标准**：
- 真机（.16/.24/.25）目录浏览正确、耗时合理；
- 上传/下载字节一致（hash 比对通过）；
- 白名单外写操作被 403 拒绝，路径穿越/命令注入无例外；
- 删除/递归删除有强确认；进度条两段真实（HTTP 段百分比 / adb 段诚实
  显示不确定态，不伪造）；
- 全链路 TDD + 双端门禁 + 真机 spike 通过。

**约束**：四层架构不跨层；零新依赖（zipfile 为内置库）；Windows
ProactorEventLoop 子进程模式；磁盘保留策略（暂存用完即清）；与方案
37 安全审查方向一致（不开新暴露面）；Chrome 两版；master 直做禁 push。

## 二、同类产品调研（ws-scrcpy 等）

立项前完成的可行性调研结论与对标学习（结合本项目优化）：

| 软件 | 文件管理实现 | 借鉴点 | 本方案取舍 |
|------|-------------|--------|-----------|
| **ws-scrcpy**（Web 同类最值得对标） | Node+adbkit 直连 ADB 做 list/stat/push/pull，命令走 WS 多路复用通道（与视频流分开）；前端文件管理器 UI，支持拖拽 APK push 到 /data/local/tmp 后安装 | 传输与视频流通道分离、任务化进度、界面分区清晰 | **采纳通道分离**（数据走 HTTP，进度走任务表轮询而非 WS——本项目无 Node/adbkit，HTTP+axios 是既有成熟基建）；APK 拖拽安装**不纳入本档**（既有安装端点已覆盖，拖拽 UI 收益低） |
| **scrcpy 2.7+** | 拖放文件 → push 到 /sdcard/Download（无目录浏览，功能轻） | 轻量推文件的直觉操作 | 不采纳（无浏览无法定位，运维需要双向管理） |
| **openstf** | 完整文件管理器（list/push/pull 全套 ADB sync 协议）+ logcat 查看导出 | 全功能管理心智（删/改名/多选） | **采纳形态**（目录表格 + 多选 + 删除重命名），logcat dump 不纳入（已有调试会话日志导出，覆盖面不同但与本档职责不重叠） |
| **QtScrcpy** | 桌面端无文件管理器 | — | 无借鉴 |

**结合本项目的优化点**（调研 → 适配）：
1. ws-scrcpy 的 WS 多路复用在 Node 侧是自然方案；本项目 HTTP 层成熟、
   axios 有原生上传/下载进度回调，**数据 HTTP + 进度轮询**比移植 WS
   通道省一整个子系统；
2. ws-scrcpy 无并发防护（多文件传输互相抢 ADB）；本项目方案 35 已治理
   连接池，**单设备单飞互斥**直接对齐既有治理语义；
3. 路径穿越/注入在 ws-scrcpy 侧依赖 adbkit 查询参数转义；本方案
   **白名单 + shlex.quote 双保险**，且在方案 37 安全审查前压住暴露面。

## 三、功能范围（用户定档决策）

- **范围档**：标准档——目录浏览 + 上传 + 下载 + 删除 + 重命名；
  不含 logcat 全文 dump 与 APK 一键安装（APK 走既有安装端点）；
- **入口形态**：独立页面 `/device/:id/files`，DeviceDetail 顶栏入口按钮；
- **设备端边界**：读全盘 / 写白名单（仅 `/sdcard`、`/data/local/tmp`）；
- **批量操作**：多选删除（逐项执行+结果汇总）+ 多选/多文件下载（后端
  zip 流式打包）；
- **传输反馈**：进度条——两段真实（HTTP 段 axios 原生百分比 + adb 段
  不确定态条纹动画），不伪造百分比。

## 四、设计

### §1 后端（四层 + 任务表 + 端点契约）

```
infrastructure/adb/cli.py（新增原语，均走既有 _run_serial 模式）
  list_dir(device_id, path)    → shell ls -la（shlex.quote；行解析按「7 前缀
    token（权限/link数/owner/group/大小/日期/时间）+ 第 8 token 起为名称」策略，
    大小列为纯数字字节、日期 YYYY-MM-DD HH:MM、软链接 `-> target` 后缀——
    2026-10-10 真机预研 A7.1（.25/.19）+ A11（.18/.13）四机列格式一致；
    2026-10-12 实施前复测（.25/.16/10.50.10.29）确认为 7 前缀 token，
    原「8 前缀」系列项计数笔误——解析器用 split(maxsplit=7) 定位前缀、
    名称列保留内部空格；输出解码 errors="replace" 容错）
  stat_size(device_id, path)   → ls -ld 解析（下载前获总量、任务表展示用）
  rename_path(d, old, new)     → shell mv（同目录重命名）
  delete_path(d, path, is_dir) → shell rm -f / rm -r
  push/pull 已有（实施补充：加可选 timeout 参数——默认 30s 会中断
    超过 30s 的大文件传输）

domain/ports.py：AdbDriver Protocol 扩展 4 个方法抽象——
    list_dir / stat_size / rename_path / delete_path（push/pull 复用既有；
    docstring 语义如既有风格）

application/file_service.py（新，核心单元）
  - WRITABLE_ROOTS = ['/sdcard', '/data/local/tmp']（读全盘 / 写白名单）
  - 安全净化：写操作目标必须 normalize 后落在白名单前缀内，否则 403；
    所有 shell 参数 shlex.quote
  - 传输任务表：内存 dict job_id → {方向, 目标路径, 大小, 状态, 设备序列}
    状态机 running(substage: pulling|pushing|zipping|http)->done|failed|cancelled；
    单设备同时仅 1 个传输（互斥 409 需新增 TransferBusyError 异常类——
    既有 ConflictError 为录屏专用消息不可复用；基类默认 400、403/404 已有
    子类先例；语义对齐方案 35 连接治理）
  - 下载：pull → tempfile → FileResponse（暂存清理挂 background 任务，
    响应体发送完成后执行；tempfile 为本项目首用、stdlib 零依赖）
  - 多选下载：逐个 pull → zipfile 内置打包 → FileResponse → finally 清理
  - 上传：UploadFile → tempfile → push → 清理；多文件逐个（单文件 512MB
    上限；项目首个 multipart 端点——python-multipart 已在 pyproject 依赖，
    零新依赖成立；既有 APK 安装端点走 apk_path 查询参数，不重复建设）

interfaces/http（devices.py 挂子路由，绕开 /{device_id} 参数路由吞路由坑）
  GET    /api/devices/{id}/files?path=...
  GET    /api/devices/{id}/file/download?paths=..（单=原文件流；多=zip）
  POST   /api/devices/{id}/file/upload?path=...（multipart，多文件逐个）
  POST   /api/devices/{id}/file/rename   {path, new_name}
  POST   /api/devices/{id}/file/delete   {paths: []}
  GET    /api/devices/{id}/file-jobs/{job_id} → {status, substage, size}
```

**传输进度模型（诚实修正）**：adb push/pull 是单命令无字节流钩子，
任务表不做逐字节记账，为状态机 + 已知总量。百分比由两端拼接：
上传＝HTTP 段精确（onUploadProgress）+ push 段模糊态；下载＝pull 段
模糊态 + HTTP 段精确（onDownloadProgress）——文件越大、HTTP 段占比
越高，百分比越真实。

### §2 前端（独立页面 + 进度条）

```
路由：/device/:id/files（懒加载 FileManager.vue），DeviceDetail 顶栏
新增「文件」入口按钮

FileManager.vue（新，独立组件）
  - 顶部：路径面包屑（逐级点击回跳）+ 刷新/返回上一级/上传按钮
  - 主体：el-table
      列 = 选择框 | 名称(图标+目录可点击进入) | 大小(人类可读) | 修改时间 | 权限
      多选 = 仅文件可多选删除/下载；目录只能单独进入或单删
  - 交互：
      · 上传：input multiple → 逐个上传，每个文件独立进度行（HTTP 段
        百分比实时，push 段显示「推入设备中…」spinner，完成打勾/失败红标）
      · 下载：单文件=直接保存；多选=后端 zip（推送段「打包中…」→
        下载段真实百分比）
      · 删除：ElMessageBox 确认（目录递归删除强确认文案 + 红字警告）→
        逐项执行结果汇总（成功 N/失败 M）
      · 重命名：dialog 输入新名（校验非法字符）→ 成功后原地刷新当前目录
  - 进度呈现：每个传输操作一行进度条（两端拼接逻辑）；
    HTTP 段字节/总量实时刷新；adb 段为不确定态进度条（条纹动画）+
    阶段文案「设备拉取中…/推入设备中…/打包中…」
  - 空态（路径不存在/403 提示）、目录空、加载失败重试
  - 设备不可用（offline）时整页提示并禁用操作
```

### §3 安全、错误处理与测试计划

**安全落点**：
- 路径净化：后端 normalize + 拒绝 `..` 逃逸；写操作白名单前缀校验
  在前、shell quote 在后（穿越/注入双层防御）；
- 写白名单（/sdcard、/data/local/tmp）覆盖上传/删除/重命名；
- 删除目录 = rm -r：白名单内 + 前端强确认双闸；
- 上传限 512MB/文件；下载无上限但受 tempfile 磁盘水线制约。

**错误映射**：
- 路径不存在/非目录 → 404；设备 offline → 400（AdbError 既有模式）；
- 写目标不在白名单 → 403；单设备并发传输 → 409；
- 任务表条目完成后 60s TTL 自动清理（对齐 debug 系统双限清理模式）。

**测试计划（TDD 逐层）**：
- cli 层：ls 输出解析（toybox 三态样张：普通/含空格名/符号链接 + 前缀
  列数边界用例）、mv/rm argv 断言、stat 解析、异常传播；
- file_service：白名单矩阵（/sdcard 内 ✓、/sdcard/../etc ✗、
  /data/local/tmp ✓、/data ✗、大小写/软链逃逸）、任务表互斥与 TTL、
  tempfile 清理验证、zip 打包完整性（解压比对）；
- HTTP 层：端点契约、403/404/409 矩阵、Content-Disposition、
  多文件 zip 响应；
- 前端：FileManager 组件（导航/多选/进度行两段态）、api 方法、
  重命名校验、删除确认文案；
- 真机 spike（tests/manual/）：ls 格式三态（.19/.13/.25/.18 已预研
  列格式一致，spike 补 .16/.24）、推拉字节一致（hash 比对）、
  白名单外写 403、zip 下载解压一致、大文件（≈50MB）两段进度观感。

## 五、数据流（主流程时序）

```
下载单文件：
  前端 GET download 请求 → 后端建任务(pulling, 查 stat_size 总量)
  → adb pull 到 tempfile → 任务转 http 态 → FileResponse 流式响应
  → 前端 axios onDownloadProgress 实时进度 → 响应完成
  → 后端 finally 删 tempfile + 任务 done（60s TTL）

上传文件：
  前端 input 选择 → axios onUploadProgress（HTTP 段实时）
  → 后端 UploadFile→tempfile → 任务置 pushing → adb push
  → 完成后删 tempfile、任务 done → 前端刷新当前目录

多选下载（zip）：
  前端多选 → 后端建任务(zipping) → 逐个 pull → zipfile 打包
  → 任务转 http 态 → zip FileResponse → 同上进度与清理
```

## 七、风险与已知限制

| 项 | 说明 | 缓解 |
|----|------|------|
| toybox ls 格式差异 | 不同真机 toybox/系统 ls 输出列宽差异 | **已预研（2026-10-10）**：A7.1（.25/.19）+ A11（.18/.13）四机 ls -la/ld 列格式一致；2026-10-12 三机复测确认为 7 前缀 token；解析器按 7 前缀 + 余下为名（split(maxsplit=7)，名称保留内部空格），不做定宽假设 |
| 非 UTF-8 文件名 | 设备存量文件可能含非 UTF-8 字节名，toybox ls 对其转义显示 | list_dir 解码 errors="replace" 不崩；转义形态名的后续操作（mv/rm/download）以显示名为准可能失败，返回清晰错误列为已知限制 |
| 大文件传输占连接 | 单设备单飞互斥下大文件 pull 期间其他操作等待 | 互斥即治理（方案 35 语义）；任务表可见当前传输状态 |
| adb 段进度无法细分 | push/pull 单命令无字节钩子 | 两段式诚实进度（HTTP 精确 + adb 不确定态），不伪造 |
| 删除误操作 | rm -r 白名单内仍可误删 | 前端强确认（红字+目录名回显）；首版不做回收站 |
| 软链逃逸 | /sdcard 内软链指向系统路径时删除/重命名可能作用到目标 | normalize 解析真实路径前缀校验；spike 补软链用例实测 |
| zip 大目录内存/磁盘 | 多选大文件打包期间 tempfile 双份占用 | zip 到 tempfile（非内存）；完成后统一清理 |
