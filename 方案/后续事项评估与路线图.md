## 1. 安全审查专项（P1）

- **范围**：后端暴露面——HTTP API 认证缺失面、路径穿越/文件名净化（`/api/export` 族）、`debug.py` shell 通道命令注入面、WS 消息解析、静态托管；绑定已限 `127.0.0.1`（降低外部暴露风险）。
- **资源**：无外部依赖；复用 `docs/reviews/` 留档机制。
- **时间**：审查 0.5 天 + 修复（预期小修）0.5 天。
- **影响面**：近零（审查不改码；修复局部）。
- **计划**：审查留档 → 逐项修复提交 → 门禁回归。无发现则仅留档。

## 2. 屏幕工具（P1）

- **范围**：录屏（`adb shell screenrecord`，系统自带零 root）→ 流式拉取 MP4 → `<video>` 预览+下载；GIF 前端抽帧；标注（canvas 叠加）。
- **资源**：真机三台；零新后端依赖。
- **时间**：录屏 1 天 + GIF 0.5-1 天 + 标注 0.5 天。
- **影响面**：低（新服务 + 面板新 tab）。
- **风险与规避**：低端设备编码器 err=-38（**.25 Android 7.1.2 已实测**：大分辨率失败 → `--size 256x144` 成功）→ 自动降档重试；大文件 → 挂方案 18 双限清理。
- **状态**：2026-10-10 调研——见方案 37。

## 3. 应用检查（P1）

- **范围**：`dumpsys activity/services` → 当前栈/top Activity/Service 清单实时展示。注意 `/api/apps`（应用列表/启动/停止/卸载/内存）已存在，本项只补**运行时状态**层，避免重复。
- **资源**：真机样本（.33 已采 mResumedActivity 可解析）；无依赖。
- **时间**：1 天。
- **影响面**：低。
- **风险与规避**：各 ROM dumpsys 格式漂移 → 键值容错解析 + 多机型样本先行。

## 8. 网络抓包（P3，Phase 2 首选大项）

- **关键约束**：真机均非 root、无 tcpdump → push tcpdump 路线不可行。两条替代：
  - A. mitmproxy 前置代理（`adb reverse` + 设备 http_proxy）——仅代理感知流量；引入 mitmproxy 依赖（破「零新依赖」惯例需用户拍板）
  - B. 设备端 VPN 抓包 apk（PCAPdroid 式）——全流量但需装 app、需长期维护 Android 包，破坏「零安装」定位
- **时间**：spike 0.5-1 天 + 实施 2-3 天 + 验收 0.5 天。
- **影响面**：高（新 traffic 域横跨采集/传输/展示/导出）。
- **风险与规避**：spike 先行止损（抓取率不达标即如实结案）；独立 traffic 域不 import 核心链；分期（HTTP 明文 pcap → HAR 解析 → HTTPS 可选）；依赖引入需用户批准。

- **若坚持**：降级为「预定义命令白名单 + 参数校验」快捷脚本（0.5 天），不做通用执行器。

## 15. 设备连接假成功治理（P2，2026-10-13 新增，✅ 2026-10-15 已实施进 0.7.9）

- **来源**：2026-10-13 用户实操反馈——两人协作场景「同事请求连接同一设备，提示连接成功，但设备列表未显示」。
- **根因（代码级）**：`cli.py:716` connect 成功判定为字符串 `"connected" in output.lower()`——adb 对已登记地址回 `already connected to …`（**不尝试重连**）同样命中 → 假成功提示；`cli.py:485` 设备列表仅保留状态为 `device` 的行，`offline` 行被过滤不显示；SSE 事件只播设备集合「新增/消失」差集，已登记但 offline 的设备无任何提示。
- **范围**：connect 链路对 `already connected` 分支补一次 `adb devices` 状态复核——offline/不在 → 返回明确失败提示（含「先断开重连」指引）；可选自动 `disconnect` 后重连一次。涉及 `AdbCliDriver.connect_tcp` + 前端连接对话框错误回显（Dashboard.vue）。
- **时间**：0.5 天。**影响面**：低（connect 链路 + 错误文案）。
- **实施记录（2026-10-15，用户反馈 .25 假成功触发）**：按评估范围落地——`connect_tcp` already connected 分支补 `_device_states()` 设备表复核，非 `device` 态抛 `DeviceNotReadyError`（400 `DEVICE_NOT_READY`，offline/unauthorized/不在表三类中文指引；fresh connected 零额外调用，scan 编排经既有 `except Exception` 自动归 failed 带原因）。前端零改动（extractApiError 原样回显后端文案）。「自动 disconnect 重连一次」未做（保持最小影响面，指引代替）。真机实证：.23（unauthorized）与 .25（offline）经新代码均从假成功改为准确拦截文案；门禁 1235 passed / cov 93.62%。列表侧 offline/unauthorized 可见性（SSE 无提示根因之一）未纳入本批，留作后续增强。
