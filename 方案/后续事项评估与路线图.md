## 1. 安全审查专项（P1）

- **范围**：后端暴露面——HTTP API 认证缺失面、路径穿越/文件名净化（`/api/export` 族）、`debug.py` shell 通道命令注入面、WS 消息解析、静态托管；绑定已限 `127.0.0.1`（降低外部暴露风险）。
- **资源**：无外部依赖；复用 `docs/reviews/` 留档机制。
- **时间**：审查 0.5 天 + 修复（预期小修）0.5 天。
- **影响面**：近零（审查不改码；修复局部）。
- **计划**：审查留档 → 逐项修复提交 → 门禁回归。无发现则仅留档。

## 2. 屏幕工具（P1）

- **范围**：录屏（`adb shell screenrecord`，系统自带零 root）→ 流式拉取 MP4 → `<video>` 预览+下载；GIF 前端抽帧；标注（canvas 叠加）。
- **资源**：真机三台；零新后端依赖。
- **时间**：录屏 1 天 + GIF 0.5-1 天 + 标注 0.5 天。
- **影响面**：低（新服务 + 面板新 tab）。
- **风险与规避**：低端设备编码器 err=-38（**.25 Android 7.1.2 已实测**：大分辨率失败 → `--size 256x144` 成功）→ 自动降档重试；大文件 → 挂方案 18 双限清理。
- **状态**：2026-10-10 调研——见方案 37。

## 3. 应用检查（P1）

- **范围**：`dumpsys activity/services` → 当前栈/top Activity/Service 清单实时展示。注意 `/api/apps`（应用列表/启动/停止/卸载/内存）已存在，本项只补**运行时状态**层，避免重复。
- **资源**：真机样本（.33 已采 mResumedActivity 可解析）；无依赖。
- **时间**：1 天。
- **影响面**：低。
- **风险与规避**：各 ROM dumpsys 格式漂移 → 键值容错解析 + 多机型样本先行。

## 4. 性能监控增强（P1-2）

- **范围**：进程级 CPU 明细（`dumpsys cpuinfo` 已采样本可解析）+ 电池/温度（`dumpsys battery` 已采）。方案 08「基础」→ 总览 Phase 2「完整」。
- **时间**：1 天。
- **影响面**：低-中（perf 采样链路加字段，仅增不改，导出格式向后兼容）。
- **风险与规避**：字段 additive；采样频率不提升（基线不回归）。

## 5. 网段扫描连接 + 列表演示缩略图（P1，2026-10-10 新增）

- **目标**：用户输入网段（如 `192.168.8.0/24`）→ 并发扫描 5555 → 尝试 adb connect → 成功者入列表并展示屏幕截图缩略图。
- **已实测证据**（2026-10-10 spike）：254 并发扫 /24 仅 **2.02s**（发现 18 主机）；三台真机在线可验证；`/api/devices/connect` 与 `/api/devices/{id}/screenshot` 已存在可复用。
- **影响面**：中（新扫描链路 + 前端列表增强）。
- **详细设计**：见 `方案/36-网段扫描连接与设备缩略图方案.md`。

## 6. 设备 offline 退避治理（P2，方案 34 D5）

- **前置**：D7 观测数据积累（真实 offline 事件）。真机拔线/`adb kill-server` 可构造。
- **时间**：1-1.5 天。**影响面**：中（stream_service 探针入口状态注入）。
- **风险与规避**：offline 信号只做「跳过本轮」不做「修改阈值」，与判死窗公式解耦；参数 config 可开关，默认关→真机验证→默认开；价值不足则如实结案。

## 7. 试用反馈收集（P2 流程项）

- 渠道已就绪（Issue 模板/Discussions/日志指引）。所需资源 = 真实使用者。
- 计划：Issue 流入 → 分类 → 每 M 条汇总回写进度追踪。

## 8. 网络抓包（P3，Phase 2 首选大项）

- **关键约束**：真机均非 root、无 tcpdump → push tcpdump 路线不可行。两条替代：
  - A. mitmproxy 前置代理（`adb reverse` + 设备 http_proxy）——仅代理感知流量；引入 mitmproxy 依赖（破「零新依赖」惯例需用户拍板）
  - B. 设备端 VPN 抓包 apk（PCAPdroid 式）——全流量但需装 app、需长期维护 Android 包，破坏「零安装」定位
- **时间**：spike 0.5-1 天 + 实施 2-3 天 + 验收 0.5 天。
- **影响面**：高（新 traffic 域横跨采集/传输/展示/导出）。
- **风险与规避**：spike 先行止损（抓取率不达标即如实结案）；独立 traffic 域不 import 核心链；分期（HTTP 明文 pcap → HAR 解析 → HTTPS 可选）；依赖引入需用户批准。

## 9. 脚本沙箱（❌ 不建议）

- 安全面大（注入/资源滥用）、设备端普遍无 Python 运行时、与远程 Shell 价值重叠。
- **若坚持**：降级为「预定义命令白名单 + 参数校验」快捷脚本（0.5 天），不做通用执行器。

## 10. 100+ 设备规模化（P3）

- **资源**：模拟设备压测（mock adb 输出 + 压测脚本）。
- **时间**：压测量化 1 天 → 瓶颈修复 1-2 天（视数据）。
- **风险与规避**：先量化再动手；N=50 无瓶颈则如实归档「规模上限证据」，不做预防性重构。
