## 一、需求映射与根因（调研 2026-10-16）

| 用户诉求 | 根因定位 | 结论 |
|----------|----------|------|
| ① 清空后撤销仍可用 | `clearAll`（ScreenshotPreview.vue 888-899）按方案 47 设计记一步 `clear` 快照（「清空可一步撤销」）；撤销按钮禁用判据为 `history.length === 0`（86 行）→ 清空后 history 非空，按钮点亮，点击整体回恢复 | 需改：语义与用户期望冲突，反转该取舍（见 §二 F1） |
| ② 什么都没画时撤销可点 | 与①同源：判据看**操作步骤栈**而非**画布内容**。删除命令记 `delete` 步 / 清空记 `clear` 步后，画布已空但 history 非空 → 按钮仍可点 | 并入 F1 统一修复 |
| ③ 点击文字选不中、反而弹出输入框 | `annotationModel.ts` `drawCmd` number 分支（443-444 行）设 `textAlign='center'`/`textBaseline='middle'` **无 save/restore**（全 frontend 唯一设置处，grep 实证）；text 分支（428-432）不设对齐、依赖 ctx 现状；而 `cmdBBox` 文字命中盒（132-136）按 left/alphabetic 假设计算。栈内一旦存在序号标注，`redraw` 全量回放时 number 把 ctx 污染，其后所有文字渲染位置整体左偏约半字宽、纵偏约半行高 → 点击**可见字形**落在命中盒外 → `onPointerDown`（526-594）视作空白 → 文字工具走「放置新文字」路径 → text-tool-row 行内输入框弹出（即「又弹出来一个输入框」）；双击编辑同因落空 | 需改：这是命中盒与渲染错位 bug，非缺功能——选中优先序（手柄>命中>空白）本就与矩形一致 |

③的复现条件补充：`[序号, 文字]` 任意先后画过即触发（redraw 每次都全量
回放，污染随栈常驻直到弹窗销毁）；仅文字无序号时渲染与命中盒一致、点击
可选中——与用户「和点击矩形的效果一样」的本意并不冲突，修好后两情形统一。

## 二、方案设计

### F1 撤销态与清空语义（T1）

按用户期望统一为「**画布为空 ⇒ 无可撤销**」：

- 撤销按钮 `:disabled` 判据改为 `commands.length === 0`（86 行）。
- `undo()` 入口加同判据守卫（`if (commands.value.length === 0) return`）
  ——覆盖 `Ctrl+Z` 快捷键绕过按钮态的路径（onKeydown 990-994 直调 undo）。
- `clearAll` 终态化：不再记 `clear` 步，改为**重置全部历史**——
  `commands=[]、history=[]、redoHistory=[]`（清空 = 重新开始）。
  `HistoryStep` 的 `clear` 变体与 undo/redo 两处 `clear` 分支（850-852、
  877-879）随之成为死代码，一并移除。
- 清空按钮加二次确认（`ElMessageBox.confirm`，Dashboard 同款组件，零新
  依赖）：清空不可撤销后，防误清必须有兜底。
- **保留**：删除单条命令仍可撤销（画布非空时撤销可用，delete 步语义不变）；
  redo 维持现状（无按钮、`Ctrl+Shift+Z` 兜底，方案 49 D2 治理结论不动）。
- **取舍说明（须用户知晓）**：反转方案 47「清空可一步撤销」设计；副作用是
  误删最后一条命令致画布空后，无法再撤销找回（用户 ② 明确要求此语义）；
  清空路径由二次确认缓解。同类先例：方案 49 D3 反转方案 43 边框独占。

### F2 文字命中错位修复（T2）

双保险 + 单测钉死，改动集中于 `annotationModel.ts` `drawCmd`：

- number 分支补 `ctx.save()/ctx.restore()` 包裹（对齐 pen/highlight 分支
  既有模式 416/425 行），不再向共享 ctx 泄漏对齐态。
- text 分支显式设 `ctx.textAlign = 'left'`、`ctx.textBaseline = 'alphabetic'`
  （与 `cmdBBox` 假设一致）再 fillText，同样 save/restore 包裹——即便未来
  其他分支引入污染，文字渲染-命中盒也不脱钩。
- 单测扩展（`annotationModel.test.ts`，fake ctx 现为空 setter 237-238 行）：
  fake ctx 记录 save/restore 深度与 fillText 时刻的 align/baseline 值。
  钉死用例：
  1. `drawCmd(number)` 执行后 ctx 的 align/baseline 与执行前一致（无泄漏）；
  2. `drawCmd(text)` 传入被污染的 ctx（预置 center/middle），fillText 时刻
     仍为 left/alphabetic；
  3. 组合回归：`[number, text]` 回放后，在 text 视觉中心坐标
     （`at.x + measure/2, at.y - px/2`）`hitTest` 命中该文字（现状落空）。

组件层零改动（`onPointerDown`/`onDblclick` 优先序与命中模型不动）；
`ScreenshotPreview.test.ts` 的 fake ctx（96-97 行）如有类型联动同步补。

## 五、验收

- vitest 全绿（含新增钉死用例）+ vue-tsc + `npx eslint .` 全量。
- 浏览器手工（Chrome）：
  1. 画两笔 → 清空 → 弹二次确认 → 确认后画布空、撤销灰、`Ctrl+Z` 无效；
  2. 画一笔 → 选中删除（Delete 键）→ 画布空 → 撤销灰（用户②场景）；
  3. 画一笔 → 删除 → 再画一笔（画布非空）→ 撤销仅回退最后一步；
  4. 画「序号 + 文字」→ 直接点击文字字形 → 选中虚线框出现（与矩形一致）；
  5. 双击文字 → 进入行内编辑（不再弹新输入框）；
  6. 仅文字（无序号）场景回归不受扰动。
- 真机 exe 冒烟：并入下轮重打包清单即可（纯前端改动，无后端面）。
