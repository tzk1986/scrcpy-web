### A1 审查范围（后端暴露面全量）

| # | 关注面 | 审查要点 |
|---|--------|----------|
| 1 | HTTP API 认证缺失 | 全端点无认证（现状缓解：绑定 127.0.0.1）。**重点评估浏览器 CSRF 面**——任意网站页面可向 `http://127.0.0.1:8765` 发起请求（读导出数据、触发 /api/system/shutdown、连接设备、执行调试命令）。评估加 **Origin/Host 校验中间件**（fetch 请求校验白名单：本地前端同源；非浏览器客户端缺 Origin 头豁免），实现代价小、收益高 |
| 2 | 路径穿越/文件名净化 | `/api/export` 族（debug.py / network.py / performance.py 三处）、sessions 日志导出：用户可控字段（文件名、ID、路径参数）是否拼接文件路径，是否净化 `../`、绝对路径、Windows 盘符、特殊字符 |

| 5 | 静态托管 | 目录限制与解析绕过 |
| 6 | 资源面 | SSE 无限订阅、上传大小限制、SQLite 查询参数化（ORM 天然参数化，确认无裸 SQL 拼接例外） |

## 子项 B：屏幕工具（P1，1.5-2.5 天：录屏 1 + GIF 0.5-1 + 标注 0.5）

### B1 录屏

- **采集**：`adb shell screenrecord`（系统自带零 root）——参数：`--bit-rate 4M`
  （默认）、`--time-limit 60`（60s 上限兜底，前端倒计时同口径）。
- **拉取方式：`adb pull` 文件，不用 exec-out**——Windows adb exec-out 二进制流
  存在 CRLF 转换风险，文件方式零转换（截图 PNG 链路既有经验可参照）。
  流程：screenrecord 写 `/sdcard/openscrcpy_rec_<ts>.mp4` → 完成后
  `adb pull` → **设备端文件立即清理**（临时产物用完即清，数据保留策略）。
- **生命周期**：`RecordingSession {id, device_id, started_at, state,
  remote_path}`；state 机：recording → stopping → pulling → done/failed；
  **单设备单录互斥**（第二路 409，同方案 36 扫描互斥模式）。stop 实现：
  `adb shell pkill -INT screenrecord` 或向进程发 SIGINT（screenrecord
  Ctrl-C 语义收尾 MP4——实施时以真机验证为准，toybox 设备可用 `kill -INT`）。
- **降档重试（已 spike 验证）**：
  - .18（Android 11）大分辨率 ✓：`--size 540x1200` 3s/16KB；
  - .25（Android 7.1.2）大分辨率 ✗ `Unable to get output buffers (err=-38)`
    → `--size 256x144` ✓ 2s/8KB；
  - 设计：启动失败且输出含 `err=-38`（编码器失败特征）→ 自动降档 `256x144`
    重试一次，再次失败才报错。
  - ✅ 2026-10-12 B-Fix-2 修复（`5c1c985`）：自动降档从「仅 2s 宽限窗内」
    扩展为「宽限窗内 + 后台任务终结时」双触发点（`_degraded_once` 防重入，
    同 start 只降档一次）——.25 晚失败（~3s 超窗）由完成回调降档，真机复验
    通过（--size 256x144 发出、stop 收敛、产物 7.5KB ftyp ✓）
- **前端**：详情页「录屏」按钮 → 录制中红点+计时 → 「停止」→ 后端收尾拉取
  → `<video>` 预览 + 下载按钮。
- **磁盘**：录屏产物落缓存目录，挂方案 18 双限清理（大小/时间双限），
  不无限增长。

### B2 GIF（前端抽帧）

## 共性：测试方向（TDD，按子项）

**A（attack-first）**：
1. 导出文件名 `../` 穿越 / 绝对路径 / 特殊字符 → 拒绝或净化（各 export 端点映射用例）；
2. debug shell 元字符注入（`;`、`|`、`$()`、引号）→ 不产生拼接执行；
3. 恶意 Origin（如 `http://evil.example`）fetch 请求 → 拒绝；
   非浏览器客户端（无 Origin 头）→ 放行（豁免）；
4. WS 非法 JSON / 缺 op 字段 → 不 500、不泄露栈。

**B**：
5. 录制生命周期 fake：start → stop 信号发对（pkill/kill -INT 参数断言）→
   pull 成功 → 设备端清理命令发出；
6. 降档重试：fake screenrecord 首启输出 err=-38 → 自动以 256x144 重试 →
