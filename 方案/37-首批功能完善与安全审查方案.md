## 子项 A：安全审查专项（P1，0.5-1 天）

### A1 审查范围（后端暴露面全量）

路由面已清点：7 个 router（`/api/apps`、`/api/debug`、`/api/devices`、
`/api/network`、`/api/perf`、`/api/sessions`、`/api/system`）+ WS + SSE +
静态托管。逐项审查关注：

| # | 关注面 | 审查要点 |
|---|--------|----------|
| 1 | HTTP API 认证缺失 | 全端点无认证（现状缓解：绑定 127.0.0.1）。**重点评估浏览器 CSRF 面**——任意网站页面可向 `http://127.0.0.1:8765` 发起请求（读导出数据、触发 /api/system/shutdown、连接设备、执行调试命令）。评估加 **Origin/Host 校验中间件**（fetch 请求校验白名单：本地前端同源；非浏览器客户端缺 Origin 头豁免），实现代价小、收益高 |
| 2 | 路径穿越/文件名净化 | `/api/export` 族（debug.py / network.py / performance.py 三处）、sessions 日志导出：用户可控字段（文件名、ID、路径参数）是否拼接文件路径，是否净化 `../`、绝对路径、Windows 盘符、特殊字符 |
| 3 | debug.py shell 通道命令注入 | shell 命令执行路径：命令是否参数化（subprocess 列表、无 `shell=True` 拼接）；用户输入（命令参数、路径、环境变量）能否注入元字符（`;&|$()`、引号） |
| 4 | WS 消息解析 | JSON 解析异常处理；`op` 分发前的字段类型校验；异常路径是否泄露栈信息 |
| 5 | 静态托管 | 目录限制与解析绕过 |
| 6 | 资源面 | SSE 无限订阅、上传大小限制、SQLite 查询参数化（ORM 天然参数化，确认无裸 SQL 拼接例外） |

### A2 方法

1. 逐文件审查（interfaces 全量 + infrastructure 执行点）——审查不改码；
2. 发现清单留档 `docs/reviews/2026-10-XX-安全审查.md`（分级：高危/中/低，
   每项含位置、复现路径、修复建议）；无发现则仅留档（同方案 17 先例）；
3. 逐项修复提交——**攻击用例先行**（TDD：先写「恶意输入被拒」测试再修复，
   例：`../` 穿越用例、shell 元字符注入用例、恶意 Origin 请求被拒用例）；
4. 门禁回归（pytest + ruff + mypy 全绿）。

### A3 时间与影响

- 审查 0.5 天 + 修复（预期小修，Origin 校验 ≤0.5 天）。
- 影响面近零：审查不改码；修复局部（如有）。

## 子项 B：屏幕工具（P1，1.5-2.5 天：录屏 1 + GIF 0.5-1 + 标注 0.5）

### B1 录屏

- **采集**：`adb shell screenrecord`（系统自带零 root）——参数：`--bit-rate 4M`
  （默认）、`--time-limit 60`（60s 上限兜底，前端倒计时同口径）。
- **拉取方式：`adb pull` 文件，不用 exec-out**——Windows adb exec-out 二进制流
  存在 CRLF 转换风险，文件方式零转换（截图 PNG 链路既有经验可参照）。
  流程：screenrecord 写 `/sdcard/openscrcpy_rec_<ts>.mp4` → 完成后
  `adb pull` → **设备端文件立即清理**（临时产物用完即清，数据保留策略）。
- **生命周期**：`RecordingSession {id, device_id, started_at, state,
  remote_path}`；state 机：recording → stopping → pulling → done/failed；
  **单设备单录互斥**（第二路 409，同方案 36 扫描互斥模式）。stop 实现：
  `adb shell pkill -INT screenrecord` 或向进程发 SIGINT（screenrecord
  Ctrl-C 语义收尾 MP4——实施时以真机验证为准，toybox 设备可用 `kill -INT`）。
- **降档重试（已 spike 验证）**：
  - .18（Android 11）大分辨率 ✓：`--size 540x1200` 3s/16KB；
  - .25（Android 7.1.2）大分辨率 ✗ `Unable to get output buffers (err=-38)`
    → `--size 256x144` ✓ 2s/8KB；
  - 设计：启动失败且输出含 `err=-38`（编码器失败特征）→ 自动降档 `256x144`
    重试一次，再次失败才报错。
- **前端**：详情页「录屏」按钮 → 录制中红点+计时 → 「停止」→ 后端收尾拉取
  → `<video>` 预览 + 下载按钮。
- **磁盘**：录屏产物落缓存目录，挂方案 18 双限清理（大小/时间双限），
  不无限增长。

### B2 GIF（前端抽帧）

- 源：录屏产物 `<video>`；canvas 抽帧（时长 ≤10s，fps 10 控体积）→ GIF 编码。
- **零新依赖约束下的成本**：GIF = 手写 LZW 编码器（~200 行，基线帧单测锁定）。
- **降级决策**：实施时若编码器成本超预期 → 降级为
  `Canvas.captureStream + MediaRecorder` 产 webm 短片段导出（原生 API 零
  依赖），GIF 作为增强留后。**先做 webm 路径（0.5 天内可完），GIF 视余量。**

### B3 标注

- 截图模式/暂停帧 canvas 叠加：画笔/箭头/矩形/文字 → 导出 PNG。
- 挂靠方案 29 截图链路已有导出能力，独立小面板（0.5 天）。

### B4 影响面

- 新 `RecordingService`（应用层）+ 详情页新 tab；零新后端依赖。
- 风险表见文末共性小节。

## 子项 C：应用检查——运行时状态层（P1，1 天）

### C1 定位（与现状边界）

`/api/apps` 已有：应用列表/启动/停止/卸载/内存。本项**只补运行时状态层**，
不重复：

- `dumpsys activity` 解析：**当前栈 / top Activity / mResumedActivity**
  （spike 已采 .33 样本，mResumedActivity 行可解析）；
- `dumpsys activity services` 解析：Service 清单（包名/类名/状态）；
- `dumpsys activity providers`（Android 10+ 可用）：Provider 清单（无则空）。

### C2 设计

- API：`GET /api/apps/{pkg}/runtime` →
  `{pkg, top_activity, resumed, services: [{name, state}], providers: [...]}`；
  解析失败项返回空清单 + `parse_warning` 字段（不整体失败）。
- **ROM 漂移容错**（核心风险对策）：全部用正则键值解析（行锚定
  `mResumedActivity: ` 前缀），不依赖行号/字段顺序；三真机样本先行采集
  （.18/.25/.33）作单测 fixture。
- 前端：应用检查界面新增「运行时」tab——当前栈/Resumed Activity 卡片 +
  Service 清单表 + 「刷新」按钮（按需查询，不做轮询）。

方案 18 持久化导出。本项 additive 增量，**仅增不改**：

- 前端：性能面板扩展——进程 CPU Top N 表格 + 温度/电压展示。

## 共性：测试方向（TDD，按子项）

**A（attack-first）**：
1. 导出文件名 `../` 穿越 / 绝对路径 / 特殊字符 → 拒绝或净化（各 export 端点映射用例）；
2. debug shell 元字符注入（`;`、`|`、`$()`、引号）→ 不产生拼接执行；
3. 恶意 Origin（如 `http://evil.example`）fetch 请求 → 拒绝；
   非浏览器客户端（无 Origin 头）→ 放行（豁免）；
4. WS 非法 JSON / 缺 op 字段 → 不 500、不泄露栈。

**B**：
5. 录制生命周期 fake：start → stop 信号发对（pkill/kill -INT 参数断言）→
   pull 成功 → 设备端清理命令发出；
6. 降档重试：fake screenrecord 首启输出 err=-38 → 自动以 256x144 重试 →
   成功；再次失败 → 报错；
7. 单设备单录互斥：第二路 start → 409；
8. webm 导出链路（captureStream → MediaRecorder 产物非空）；
9. 标注：画布叠加后导出 PNG 尺寸/内容断言（后端为零，前端 canvas 测试）。

**C**：
10. dumpsys activity 解析：三真机样本 fixture 断言 top/resumed；
    漂移样本（注入未知格式行）→ 空结果 + parse_warning 不抛；
11. runtime 端点：GET /api/apps/{pkg}/runtime 精确断言。

**D**：
12. cpuinfo 进程级解析（样本 fixture）；
13. battery 全字段解析（温度/电压/health）；
14. 导出 additive：新字段追加后旧字段序列化不回归（方案 18 既有测试扩展）。
