# OpenScrcpy 项目总览

## 项目定位

**OpenScrcpy** 是一个基于 scrcpy 的 Web 化开源远程控制与调试平台，核心差异化能力是**无限调试**——让用户在浏览器中获得接近 adb + Android Studio + Chrome DevTools 三合一的体验。

## 技术栈

- **后端**：Python 3.11+ / FastAPI / asyncio / SQLite
- **前端**：Vue 3 / TypeScript / Vite / Element Plus
- **设备通信**：ADB CLI / scrcpy-server
- **传输协议**：WebSocket（主） / WebTransport（Chrome 优化）
- **部署**：Docker / Docker Compose

## 架构设计

```
┌─────────────────────────────────────────┐
│         前端 (Vue 3 + Chrome)            │
│  Dashboard / DeviceDetail / DebugPanel  │
└─────────────────────────────────────────┘
                    ↓ WebSocket / REST
┌─────────────────────────────────────────┐
│         后端 (FastAPI + Python)          │
│  Interface → Application → Domain       │
│                    ↑                     │
│              Infrastructure              │
│  (ADB Driver / SQLite / scrcpy)         │
└─────────────────────────────────────────┘
                    ↓ ADB
┌─────────────────────────────────────────┐
│           Android 设备池                 │
└─────────────────────────────────────────┘
```

## 分层架构

### 1. Domain Layer（领域层）
- **职责**：纯业务逻辑，无框架依赖
- **文件**：`backend/app/domain/`
- **核心**：DeviceInfo、DebugSession、Ports（抽象接口）

### 2. Application Layer（应用层）
- **职责**：用例编排，协调领域对象
- **文件**：`backend/app/application/`
- **核心**：DeviceService、DebugService、StreamService

### 3. Infrastructure Layer（基础设施层）
- **职责**：具体实现，与外部系统交互
- **文件**：`backend/app/infrastructure/`
- **核心**：AdbCliDriver、SqliteRepository、ScrcpyEncoder

### 4. Interface Layer（接口层）
- **职责**：HTTP/WebSocket 端点
- **文件**：`backend/app/interfaces/`
- **核心**：HTTP routers、WebSocket handlers

## 核心设计原则

### 1. 依赖倒置
业务逻辑依赖抽象接口（Protocol），不依赖具体实现。

```python
# 业务层依赖抽象
class DeviceService:
    def __init__(self, adb: AdbDriver, repo: DeviceRepository):
        self.adb = adb  # Protocol
        self.repo = repo  # Protocol

# 基础设施层提供实现
class AdbCliDriver(AdbDriver):
    async def list_devices(self) -> list[str]:
        # subprocess 调用 adb
```

### 2. 配置与实现分离
所有参数集中在 `config/` 目录，不改代码。

```yaml
# config/base.yaml
stream:
  max_size: 1080
  bit_rate: 4M
  codec: h264
```

### 3. 可测试性
每一层都可以独立测试。

```python
# 单元测试（mock 依赖）
def test_device_service(mock_adb, mock_repo):
    service = DeviceService(mock_adb, mock_repo)
    # 测试业务逻辑

# 集成测试（真实依赖）
async def test_sqlite_repository():
    repo = SqliteRepository(":memory:")
    # 测试持久化
```

### 4. Chrome 专属优化
充分利用 Chrome 能力，不兼容其他浏览器。

- WebCodecs（H.264 解码）
- SharedArrayBuffer（零拷贝）
- WebTransport（低延迟）
- FileSystem Access（本地文件）

## 关键指标

| 指标 | 目标值 |
|------|--------|
| 视频延迟 | < 150ms（局域网）|
| 日志延迟 | < 100ms |
| Shell 响应 | < 50ms |
| 日志吞吐 | 5000 条/秒 |
| 内存占用 | < 200MB（前端）|

## 风险与应对

| 风险 | 影响 | 概率 | 应对 |
|------|------|------|------|
| scrcpy-server 集成复杂 | 高 | 中 | 提前 PoC，备选 FFmpeg |
| WebCodecs 兼容性 | 中 | 低 | 仅 Chrome，MSE 降级 |
| ADB 连接不稳定 | 高 | 高 | 自动重连、TCP/IP 备用 |
| 性能瓶颈（多设备）| 中 | 中 | 进程池、按需启动 |
