# 方案 46：录屏产物独立页面方案

> **状态**：实施完成（2026-10-14）——四项待拍板已决（见 §六），已全链实施并真机冒烟通过。
> **背景**：用户要求「视频录屏后需要下载视频或者看录屏做一个新的页面进行处理，
> 不要在设备当前页面处理，简化当前页面的内容」。

## 一、背景与目标

**现状**：录屏产物（mp4）的全部处理都在设备详情页头部的 `RecordingPanel` 内完成——
`done` 态内嵌 200×112 `<video>` 预览 + 下载链接 + 导出 webm + 重新录制按钮，
挤压设备页操作区（文件/截图/断开后排一长串），且**历史产物无处可看**：
会话终态会被下一次 start 覆盖，前端只有「当前设备当前会话」一个入口。

**目标**：
1. **独立「录屏」页**（全局）：列出历史录屏产物，支持播放、下载、删除；
   导出 webm 能力迁入本页；
2. **设备页简化**：录屏只留「启停控制」（空闲按钮 / 录制中红点计时 + 停止）；
   产物处理（预览/下载/webm）全部移出，`done` 态收敛为轻量提示 + 跳转链接。

**约束**：零新依赖；master 直做；门禁四件套（ruff + mypy strict + pytest cov≥80 +
vitest/vue-tsc）；不动抓帧/流链路；存量 API 只增不改（`/api/recording/{device_id}`
系列语义保持）。

## 二、现状调研（2026-10-14）

### 2.1 前端

- `RecordingPanel.vue`（方案 37 B5 + 方案 42 §4）：三态 `idle / recording / done`；
  - mount 经 `getRecording` 恢复会话态（recording 按 `started_at` 续计时；done + local_path 进预览态）；
  - `done` 态：预览 `<video>` + 下载 `<a>` + 导出 webm + 重新录制 + 产物大小行，
    全部指向 `GET /api/recording/{device_id}/file`；
  - 409 互斥提示；卸载时录制中仅提示服务端兜底收尾（不主动 stop）。
- 设备页 `DeviceDetail.vue` actions：`[文件] [截图] [断开] [RecordingPanel]`。
- 路由仅 3 页（`/`、`/device/:id`、`/device/:id/files`）；
  `App.vue` 顶部 `el-menu` 目前仅一项「Dashboard」。
- 产物大小展示先例：`file_size`（后端 stat 回传）；mp4 时长前端可从 `<video>`
  metadata 读取（本方案第一版不列表化展示时长，见 §3.5）。

### 2.2 后端

- `recording.py`（prefix `/api/recording`）现有 5 端点：
  `POST {device_id}/start|stop`、`GET {device_id}`、`GET {device_id}/file`、`GET`（列表）；
  **列表只回进行态会话**，历史「以落盘文件为准」（方案 37 B3 评审关注点①）——
  而落盘文件目前**没有任何列表接口**。
- 落盘命名：`{recording.dir}/openscrcpy_rec_{session_id}.mp4`
  （`LOCAL_FILE_GLOB = "openscrcpy_rec_*.mp4"`；`session_id` = 12 位 hex；
  本地名 = `basename(remote_path)`，pull 后同名）。
  ⚠ **文件名不含设备标识**——历史列表无法区分产物出自哪台设备（多设备场景必然残缺）。
- 双限清理（方案 42 §3）：`retention_days: 3` + `max_total_mb: 512` 按 `LOCAL_FILE_GLOB`
  扫描目录执行；关服清盘 `cleanup_all_recordings` 同 glob。**前缀不变则清理逻辑零影响**。
- `file` 端点既有 containment 先例：`resolve()` 后必须落在 `resolve_dir()` 内 +
  文件真实存在，否则 404 不泄露目录结构——新下载端点沿用同模式。

### 2.3 关键约束

- **http 播放无阻碍**：原生 `<video>` 播 H.264 MP4 不受 WebCodecs `[SecureContext]`
  限制——现状设备页 done 态内嵌预览已是实证（局域网 http 下正常播放）；
- 录屏会话互斥、自愈巡检、自然结束监听（方案 42 §1/§2）均在本方案中**保持不变**。

## 三、设计

### 3.1 需求分解

| 需求 | 落点 |
|---|---|
| 历史产物列表（时间/大小/设备） | 新页 + 新后端列表接口（扫盘） |
| 播放 / 下载 | 新页（行内播放器）+ 新下载接口 |
| 导出 webm（现状能力保留） | 迁入新页播放器区 |
| 产物删除 | 进第一版（§六-1 已拍板） |
| 设备页简化 | `RecordingPanel` `done` 态收敛 |
| 录制启停控制 | 留在设备页（不变） |

### 3.2 路由与导航

- 新路由 `/recordings`（`name: 'recordings'`，懒加载 `Recordings.vue`）；
- `App.vue` 顶部菜单新增「录屏」项（与 Dashboard 并列；菜单现已 `:router="true"`）；
- 设备页 `RecordingPanel` `done` 态提供「查看录屏」链接 → `/recordings?device=<id>`；
  进入后按 query 过滤该设备产物，顶部显示「仅看 <设备>」+ 清除按钮（已拍板 §六-2）。

### 3.3 落盘命名改造（列表设备信息的前提）

新命名（仅影响**新产生**的文件）：

```
openscrcpy_rec_{dev}__{session_id}.mp4
```

- `dev` = sanitize(device_id)：`[^A-Za-z0-9._-]` → `-`
  （`192.168.8.18:5555` → `192.168.8.18-5555`；`rk3568_r` 原样）；
- 分隔符 `__`（双下划线）：解析用 `stem.rsplit('__', 1)`（从右一次分割，
  天然不受 `dev` 内单 `_` 影响；右侧段须为 12 位小写 hex 才接受，双保险）；
- 设备端与本地仍同名（`remote_path` basename 即本地名，`pull_recording` 零改动）；
- 兼容旧文件：`openscrcpy_rec_{12hex}.mp4` 解析为「设备未知」，
  列表照常展示/播放/下载（标注「未知设备（旧版产物）」）；
- 清理面零影响：`LOCAL_FILE_GLOB` 前缀不变（前缀后 `*` 通吃新旧两种）；
- 改动点：`recording_service.start` 的 `remote_path` 生成（唯一源头）；
  存量断言测试同步更新（§四 T1）。

### 3.4 后端新接口（`recording.py` 扩展）

| 端点 | 语义 |
|---|---|
| `GET /api/recording/files` | 历史产物列表：`resolve_dir()` 按 `LOCAL_FILE_GLOB` 扫盘 → 每项 `{filename, device, session_id, size_bytes, created_at}`；`device/session_id` 按 §3.3 解析（旧格式 device=null）；`created_at` 取 mtime（ISO）；按 mtime **降序**；目录不存在 → 空列表（不报错） |
| `GET /api/recording/files/{filename}` | 下载/播放：`filename` 白名单校验（必须匹配 `openscrcpy_rec_*` 且不含路径分隔符）→ `resolve()` containment → `FileResponse(video/mp4)`；不满足 → 404 `NO_RECORDING`（同现有不泄露语义） |
| `DELETE /api/recording/files/{filename}` | 删除单产物（已拍板进第一版）：校验同下载；删除成功返回 `{"deleted": true}`；不存在 404。用于「手动即时腾空间」，与双限自动清理并存 |

- 与现有 `GET /api/recording`（进行态列表）**并存不冲突**；
  FastAPI（Starlette）路由**按声明顺序匹配**——`GET /files` 与
  `GET /files/{filename}` 必须声明在 `GET /{device_id}` **之前**，
  否则 `/files` 会被 `{device_id}` 吞掉（`files` 不是合法设备 id 但会先进处理函数）。
  路径白名单校验参考方案 39 rename 先例；
- 下载端点不复用 `{device_id}/file`（后者绑定「当前会话」，历史文件无会话）。

### 3.5 前端新页 `Recordings.vue`

- 结构：页头（标题「录屏」+ 刷新按钮）+ 列表 + 空态；
- 列表行：`设备 | 创建时间 | 大小 | [播放] [下载] [删除]`
  - `?device=<id>` 进入时按该设备过滤，顶部显示「仅看 <设备>」+ 清除按钮（已拍板）；
  - 设备列：`device` 原样展示（无别名映射，与 Dashboard 口径一致）；
    旧格式产物显示「未知设备（旧版产物）」（文案已拍板维持暂拟）；
  - 大小列：`(size_bytes/1048576).toFixed(1) MB`（沿用面板口径）；
- 播放：点击「播放」弹出 `el-dialog` + `<video controls autoplay>`（src 指向下载端点）
  + 「下载」「导出 webm」按钮（`webmExporter` 复用，逻辑照搬 `RecordingPanel` 现实现）；
- 下载：`<a :href :download>`（同现状模式，浏览器原生下载）；
- 删除：`ElMessageBox.confirm` 二次确认 → `DELETE` → 刷新列表；
- 空态：「暂无录屏。在设备页开始录制后，产物会出现在这里。」+ 引导按钮回 Dashboard；
- 刷新时机：页面挂载加载一次；手动刷新按钮；不引轮询（录制中的会话由设备页管理）。

### 3.6 设备页简化（`RecordingPanel` 改造）

  移除 `videoEl` 相关代码与样式，即删掉面板内预览/下载/webm 导出全部逻辑）。

## 五、风险与限制

1. **命名改造的存量兼容**：旧文件不可回溯设备信息（不可逆，接受并显式标注）；
   双限清理与前缀兼容已核（`LOCAL_FILE_GLOB` 不变）；
2. **文件名长度**：USB serial 极长场景 + 前缀 + `__` + 12hex ≈ 60+ 字符，
   Android/Windows 文件名长度上限（255）内，无需截断；
3. **列表规模**：双限清理（512MB 上限）约束单页规模，第一版不分页（产物数量级
   由容量上限天然约束）；若后续调大双限再评估分页；
4. **播放兼容**：`screenrecord` 产物为标准 H.264 MP4，Chrome 原生播放（现状实证）；
   降档产物（256x144）同样可播；
5. **设备页卸载提示**：现状「录制仍在继续」提示保留不动（不属本方案范围）。
