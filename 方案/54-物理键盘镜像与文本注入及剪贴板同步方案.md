# 方案 54：物理键盘镜像、文本注入升级与剪贴板同步

> 状态：已实施 T1–T4（2026-10-30，协议层冒烟全绿，拟随 v0.7.17）　|　提出版本：v0.7.16　|　日期：2026-10-30
> 来源：与上游 scrcpy v5.0.1 / ws-scrcpy / STF 类设备农场平台功能对标（路线图第 20/21 项，用户指示优先立项）。
> 硬约束（用户明示）：**保留现有 `adb shell input` 兜底链**——控制通道不可用时仍能输入，新能力不得引入单点。

## 1. 背景与目标

设备详情页（Dashboard 起流）现有输入能力=鼠标/触摸（点击、滑动、长按）+ 底部 4 个虚拟键（返回/主页/多任务/菜单，`VideoPlayer.vue:74-83`）。**无法敲物理键盘、无法输入文本（尤其中文）、无法与设备剪贴板互通**——QA 表单填写、聊天类应用测试、复制设备内容到备注等场景全部受阻。

目标（三项一体，均为上游有、我们断在前端）：

- **G1 键盘镜像**：浏览器聚焦视频区后，物理键盘按键（含修饰键、长按重复、Esc/Backspace/Enter/方向键/功能键）实时注入设备。
- **G2 文本注入**：中文/多行/粘贴文本一次性送入设备焦点输入框。
- **G3 剪贴板同步**：浏览器 ⇄ 设备双向——设备复制的内容可取到浏览器；PC 文本可写入设备剪贴板并粘贴。

非目标（本期不做，留观察）：UHID/AoA 物理 HID 模拟（Web 无法直投 USB HID）；ADBKeyboard IME 方案（G2 若实测中文不过关再单独立项）；autosync 常开推送（见 D3 拍板点）。

## 2. 现状调研结论（2026-10-30 代码级 + 上游源码级实证）

### 2.2 上游源码实证（v5.0 服务端，`logs/upstream/` 留档）

拉取 `ControlMessage.java / ControlMessageReader.java / DeviceMessageWriter.java / Controller.java / Server.java` 五件核对，关键结论：

1. **消息编号**：`TYPE_GET_CLIPBOARD=8`、`TYPE_SET_CLIPBOARD=9`（本项目 10=SET_DISPLAY_POWER、17=RESET_VIDEO 与上游一致）。
   - `SET_CLIPBOARD` 线格式：`type(1) + sequence(8) + paste(1) + len(4) + utf8`；
   - `GET_CLIPBOARD`：`type(1) + copyKey(1)`；
   - device→host `DeviceMessage`：`CLIPBOARD: type(1)+len(4)+utf8`、`ACK_CLIPBOARD: type(1)+sequence(8)`。
2. **剪贴板读写不依赖 autosync**：`Controller.handle` 对 GET/SET 无条件分发（`Controller.java:381-385`）；`clipboard_autosync=false` 时 `getClipboard()` 走主动读取并回 `CLIPBOARD` 消息（L687-705）。**autosync 只决定「设备复制时是否自动推送」的监听器注册**（L146-161）。
3. **`setClipboard(text, paste=true)` 写剪贴板后自动注入 `KEYCODE_PASTE`**（L707-727，Android≥7）——上游 MOD+V 的中文输入正道：**经剪贴板+粘贴键绕开 INJECT_TEXT 的字符限制**。写剪贴板用 hidden API（shell 身份），免 root。
4. **`GET_CLIPBOARD(copyKey=COPY)` 先注入 `KEYCODE_COPY` 再读**——可捕获设备当前选中文本，无需用户先按复制。
5. **INJECT_TEXT 服务端上限 300 字符**（`ControlMessageReader.INJECT_TEXT_MAX_LENGTH=300`），超长需分段。
6. **键盘模式约束**（官方 `doc/keyboard.md` 已取回）：sdk 模式（即本方案通道）「works everywhere, but limited to ASCII and some other characters」；上游默认字母走 KeyEvent、数字符号走 text event（`--prefer-text` 可反转）；key repeat 默认转发。
7. **控制 socket 全双工可用**：tunnel_forward 为 `adb forward` 的 TCP 连接，上游即在同一条 socket 上双向收发（reader 收 DeviceMessage）。我方现仅用 writer 方向，加 reader 无协议障碍。

## 3. 方案设计

### 3.1 G1 键盘镜像

**前端**（`VideoPlayer.vue` + 新模块）：

- 视频容器 `tabindex=0` 聚焦化 + 「键盘捕获」开关徽标（默认鼠标点击视频区取得焦点即捕获；`Esc`×2 或失焦退出，避开浏览器固有快捷键死锁）。
- 新 `frontend/src/services/keycodeMap.ts`：`KeyboardEvent.code`（物理键位，跨布局稳定）→ Android KEYCODE 全表（字母26+数字10+符号~20+功能键 F1-F12+导航+小键盘）；`key.length===1 && 非 ASCII`（中文 IME 单字符）不参与 keydown 镜像，交 composition 路径（3.2）。
- 修饰键：`ctrl→16 / shift→1 / alt→2 / meta→0x10000`（Android `KeyEvent.META_*`，实施时对 KeyEvent.java 复核）合成 `metaState` 位掩码。
- 事件语义：`keydown` → `down:true`（`e.repeat` 透传 repeat=1，上游 sdk 模式原生处理长按重复）；`keyup` → `down:false`；blur 时把仍处 down 的键全部补发 up（防卡键）。
- **顺带补滚轮**：`wheel` 事件 → `{action:'scroll'}`（后端通道现成，表单页必需）。
- 浏览器冲突处理：捕获态下 `preventDefault` 白名单制——`Ctrl+R/W/T/L` 等浏览器致命组合默认**放行给浏览器**（防止误锁），设备侧组合靠 Win/Meta 键位与页面「退出捕获」兜底；具体表进实现细化，验收判据含「浏览器可正常关页」。
- Page Visibility 停用输入逻辑（方案 17）沿用：tab 隐藏时停镜像并补 up。

**协议扩展（向后兼容）**：`{action:'key', keycode, down?:bool, repeat?:int, meta?:int}`——缺省 `down` 时维持现 DOWN+UP 成对行为，4 虚拟键等旧调用零改动。`video.py` 消息协议注释与 `docs/API.md` 同步。

**兜底链（硬约束）**：控制不可用时 `_fallback_adb_input` 保留并升级：
- key：映射表内常见键降级 `adb shell input keyevent <KEYCODE>`（keyevent 无 up/down 语义=点击等效，长按重复与修饰键丢弃——如实记录）；
- 与现状一致：仅控制通道失败（`control_send_failed`/`control_socket_unavailable`）时触发，不新增判定。

### 3.2 G2 文本注入

前端新增两入口，后端零改动（`sendText` 通道已通）：

- **IME 捕获**：聚焦态挂隐藏 `<input>`（`compositionstart/update/end`），浏览器输入法确认后整段 `end` 文本 → `{action:'text'}`；字母数字若同时被 keydown 镜像，需**互斥规则**：composition 激活期间抑制对应 keydown（防双写）。
- **「输入文本」对话框**：工具栏按钮（与 4 虚拟键并排），多行 textarea + 发送；超 300 字符**前端分段**发送（上限实证 §2.2-5）。
- 中文可靠性：INJECT_TEXT 走 KeyEvent unicodeChar，多数 App EditText 可上屏但**官方声明 limited to ASCII and some other characters**——验收以真机矩阵记录实况（.19/.22/.18 三类 ROM）；**中文主路径推荐 G3 的剪贴板粘贴**（§3.3，paste=true 一步完成），对话框内提供「以剪贴板方式粘贴」选项。若实况不达标，ADBKeyboard IME 另案。
- 兜底：控制不可用时 text 仍降级 `adb shell input text`（现实现保留，含空格 `%s` 转义卫生）。

### 3.3 G3 剪贴板同步

**方向 A：浏览器 → 设备（写+粘贴）**：
- 前端：对话框「粘贴到设备」/`Win+V` 捕获组合（用户手势内 `navigator.clipboard.readText()`，浏览器权限模型要求手势——**不可自动静默读**）→ WS `{action:'clipboard_set', text, paste?:bool}`。
- 后端：`control_sender.set_clipboard(sequence=0, paste, text)`（新增消息封装）；`paste=true` 时设备直接粘进焦点框（中文无忧，Android≥7）。
- 兜底：控制不可用 → `adb shell input text`（ASCII 部分尽力）；对话框文案提示降级态。

**方向 B：设备 → 浏览器（拉取式）**：
- 后端：控制 socket **新增 DeviceMessage reader**（全双工，§2.2-7）：解析 `CLIPBOARD(type)` 帧 → 与 `{action:'clipboard_get'}` 请求按 FIFO 关联，经视频 WS 回 `{type:'clipboard', text}`；无 reader 响应超时（3s）回 `{type:'clipboard_error'}`。
- 前端：工具栏「取设备剪贴板」按钮 + 「复制选中文本」变体（`copyKey=COPY`，先注入 COPY 键捕获当前选中，§2.2-4）；取回文本弹入「输入文本」对话框（浏览器手势内 `writeText` 可自动、否则提供手动复制区）。
- 与 autosync 无关：起流参数**维持 `clipboard_autosync=false` 不动**——拉取式覆盖 QA 场景；常开推送（设备每次复制即弹）列为 **D3 拍板点**默认不做（无 reader 常驻解析压力小、防敏感内容无感外流，观察后议）。
- 安全：剪贴板内容经 WS 明文仅本机回环（M1 已收口），不入日志正文（`logger` 只记长度）。

### 3.4 测试矩阵

- 单测：keycodeMap 全表/metaState 合成/composition 抑制规则；协议向后兼容（无 down 字段旧格式）；`set_clipboard/get_clipboard` 字节级封包（比对 §2.2 线格式）；DeviceMessage reader 帧解析（含半包/粘包）；300 字符分段。
- 真机冒烟（8766/5039 隔离；协议层 `tests/manual/smoke_54.py` **10 判据全 PASS**（2026-10-30，默认设备 .25，另 .22/A9 交叉全通），浏览器手感层 ①~⑦ 为人工验收清单）：①打字表单（英文/数字/符号/退格/回车/方向键）；②长按 repeat 不卡键；③中文 INJECT_TEXT 实况记录 + 剪贴板 paste 双路径；④设备复制→取回、PC 复制→粘贴进设备输入框；⑤失焦/Esc 退出后浏览器快捷键复原；⑥拔网断控→兜底链可输入（keyevent/text）；⑦截图模式（HTTP 帧+WS 输入）键盘同样可用。
- **设备个例记录（2026-10-30）**：.19 clipboard_get 不回帧——上游留档核对（`ControlChannel.java` DeviceMessageWriter 绑 control socket、`Controller.java` getClipboard 对 `text==null` 静默不回）+ .22/.25 交叉全通，定论 .19 ROM 个例（ClipboardManager hidden API 失效），后端正确降级 `clipboard_error` 不断控（兜底语义实证）；同机 server stderr 不逐行转发（`server_ready_timeout` 但出流正常）同归个例不深修。故冒烟默认设备用 .25。
- 门禁：pytest/ruff/mypy + vitest/vue-tsc/eslint 全量零红。

## 5. 风险与取舍

| 风险 | 应对 |
|---|---|
| 浏览器快捷键冲突致误锁 | preventDefault 白名单制 + 双重 Esc/徽标一键退出；验收含关页判据 |
| 中文 INJECT_TEXT 设备侧不可靠（官方限定） | 中文主路径走剪贴板 paste；真机矩阵记实况；不达标另立 ADBKeyboard 案 |
| 卡键（up 丢失） | blur/visibility 补发 up；兜底态 keyevent 天然点击语义无卡键 |
| 剪贴板敏感内容外流 | 拉取式（用户显式触发）默认，不常开推送（D3）；日志不落正文 |
| reader 引入并发面（控制 socket 读） | 单一后台 task + 有界队列 + 超时降级 `clipboard_error`，不触碰视频帧路径 |
| 兜底链与能力表错位（keyevent 无修饰键/长按） | 兜底降级语义如实写入文案与手册，不承诺等效 |
