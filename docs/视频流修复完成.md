# 视频流修复完成报告

## 日期
2026-09-09

## 问题描述

视频流无法正常工作，服务器在协议握手后立即关闭连接，没有发送视频数据。

## 根本原因

通过对比 py-scrcpy-client 和手动调试，发现以下问题：

### 1. 协议握手解析错误

**错误实现**：
```python
# 读取设备名后直接读取"分辨率"
device_name = await reader.readexactly(64)
resolution = await reader.readexactly(4)  # 错误！
```

**实际协议（scrcpy v2.4）**：
```python
# 1. Dummy byte (1 字节)
dummy = await reader.readexactly(1)  # 0x00

# 2. 设备名 (64 字节)
device_name = await reader.readexactly(64)

# 3. Codec 名称 (4 字节 ASCII 字符串)
codec = await reader.readexactly(4)  # "h264"

# 4. 宽度 (4 字节 uint32，大端序)
width = struct.unpack(">I", await reader.readexactly(4))[0]

# 5. 高度 (4 字节 uint32，大端序)
height = struct.unpack(">I", await reader.readexactly(4))[0]
```

**症状**：
- 分辨率显示为 26674x13876（实际是 "h264" 的 ASCII 码）
- 协议不同步，服务器认为客户端异常

### 2. JAR 文件缺失

scrcpy-server 退出时会自动删除设备上的 JAR 文件，因此每次启动前必须重新推送。

**错误**：没有推送 JAR 就直接启动服务器，导致 "Aborted" 错误（返回码 134）。

**解决**：在 `ServerManager.push_server()` 中确保每次启动前都推送 JAR。

## 修复内容

### 文件 1: `backend/app/infrastructure/stream/scrcpy.py`

**修改 1**: 更新协议握手解析
```python
# 读取 codec 名称（4 字节 ASCII 字符串）
codec_data = await asyncio.wait_for(
    self._reader.readexactly(4),
    timeout=2.0,
)
codec_name = codec_data.decode("ascii")
logger.info("scrcpy_codec", device=device_id, codec=codec_name)

# 读取宽度（4 字节 uint32，大端序）

    self._reader.readexactly(4),
    timeout=2.0,

width = struct.unpack(">I", width_data)[0]

# 读取高度（4 字节 uint32，大端序）
height_data = await asyncio.wait_for(
    self._reader.readexactly(4),
    timeout=2.0,
)
height = struct.unpack(">I", height_data)[0]
```

**修改 2**: 更新文档注释
```python
协议握手流程（scrcpy v2.4）：
    1. 服务器发送 1 字节 dummy byte (0x00)
    2. 服务器发送 64 字节设备名（UTF-8，null 填充）
    3. 服务器发送 4 字节 codec 名称（ASCII 字符串，如 "h264"）
    4. 服务器发送 4 字节宽度（uint32，大端序）
    5. 服务器发送 4 字节高度（uint32，大端序）
    6. 之后开始发送 H.264 视频数据
```

## 关键技术点

### 1. scrcpy v2.4 协议

**服务器启动参数**：
```python
cmd = [
    "adb", "-s", device_id, "shell",
    "CLASSPATH=/data/local/tmp/scrcpy-server.jar",
    "app_process", "/",
    "com.genymobile.scrcpy.Server",
    "2.4",                              # 版本
    "log_level=info",
    "max_size=1080",
    "max_fps=30",
    "video_bit_rate=4000000",
    "video_codec=h264",                 # 必须指定
    "tunnel_forward=true",              # server 监听模式
    "send_frame_meta=false",            # 不发送帧元数据
    "control=true",                     # 必须启用控制
    "audio=false",
    "show_touches=false",
    "stay_awake=false",
    "power_off_on_close=false",
    "clipboard_autosync=false",
]
```

**注意**：
- 不指定 `video_encoder`，让服务器自动选择可用的编码器
- RK3288 设备使用 `OMX.rk.video_encoder.avc`，不是 `OMX.google.h264.encoder`

### 2. 双连接协议

必须建立两个连接：
1. **视频 socket**: 用于接收视频数据
2. **控制 socket**: 用于发送控制指令（即使不使用也必须建立）

```python
# 视频连接
self._reader, self._writer = await asyncio.open_connection("127.0.0.1", port)

# 控制连接
_, self._control_writer = await asyncio.open_connection("127.0.0.1", port)
```

### 3. Socket 名称

scrcpy v2.x 使用固定 socket 名称 `"scrcpy"`，不是 `"scrcpy_<scid>"`。

### 4. ADB 端口转发

```bash
adb forward tcp:27183 localabstract:scrcpy
```

Python 作为 TCP 客户端连接 `127.0.0.1:27183`，ADB 将连接转发到设备端 server 的监听 socket。

## 经验总结

### 1. 协议文档的重要性

scrcpy 官方没有详细的协议文档，需要通过以下方式获取准确信息：
- 参考 py-scrcpy-client 源码
- 手动调试，观察实际发送的数据
- 查看 scrcpy-server 源码（Device.java, Streamer.java）

### 2. 版本兼容性

不同版本的 scrcpy-server 协议可能有差异：
- v2.x: 固定 socket 名称 "scrcpy"
- v4.x: 使用 "scrcpy_<scid>" 格式

必须确保客户端实现与 server 版本匹配。

### 3. 设备编码器差异

不同设备支持的编码器不同：
- RK3288: `OMX.rk.video_encoder.avc`
- 通用: `OMX.google.h264.encoder`

建议不指定编码器，让服务器自动选择。

### 4. Windows 环境注意事项

Git Bash 会自动转换路径（如 `/data/local/tmp` → `C:/Program Files/Git/data/local/tmp`），导致 ADB 命令失败。

**解决方法**：
```bash
MSYS_NO_PATHCONV=1 adb push ...
```

或在代码中使用 `subprocess` 时设置环境变量。
