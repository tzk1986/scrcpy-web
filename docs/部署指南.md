# 部署指南

> 本指南描述 scrcpy-web 当前**受支持的运行方式**。项目依赖 Windows 专属组件
> （ConPTY/pywinpty、scrcpy.exe、asyncio ProactorEventLoop），因此**主交付目标为
> Windows 本地运行**（未来打包为绿色免安装 exe，见文末）。Docker/Linux 配置仅作
> 服务器化方向的开发参考，**未实测验证**，暂不作为受支持发布路径。

## 环境要求

- 操作系统：Windows 10/11（当前唯一实测平台）
- Python 3.11+
- Node.js 20+
- ADB（Android Debug Bridge），设备已通过 `adb connect <ip>:5555` 连接
- Chrome 浏览器（最新两个稳定版；前端使用 WebCodecs 等 Chrome 特性）

## 开发运行

### 安装依赖

```bash
# 后端（含 dev 工具链：pytest/ruff/mypy）
pip install -e ".[dev]"

# 前端
cd frontend && npm ci

# E2E 编排依赖（仅首次；跑 E2E 时需要）
npm install && npx playwright install chromium
```

### 启动

```bash
# 一键拉起后端 + 前端 dev server
make dev
```

或手动分别启动：

```bash
# 后端：默认监听 8765
python run_server.py

# 前端：dev server 监听 8080，/api 与 /ws 代理到后端
cd frontend && npm run dev
```

访问前端：<http://localhost:8080>
后端健康检查：<http://localhost:8765/health>
API 文档：<http://localhost:8765/docs>

## 端口配置

默认后端端口 **8765**、前端 dev 端口 **8080**。后端端口可配置，`BACKEND_PORT`
被三处读取：

- `run_server.py` → `config.settings` 读取 `BACKEND_PORT`（也支持仓库根 `.env`）
- `frontend/vite.config.ts` → 代理目标读取 `process.env.BACKEND_PORT`（仅进程环境变量，不读 `.env`）
- `tests/e2e/playwright.config.ts` → `webServer` 启动参数读取 `${BACKEND_PORT}`

覆盖方式：

```bash
# 1) 进程环境变量（推荐；需在同一终端分别启动后端与前端，两边才都跟随）
BACKEND_PORT=9000 python run_server.py
BACKEND_PORT=9000 npm run dev        # 在 frontend/ 下执行，代理跟随同一端口

# 2) 仓库根 .env 文件（dotenv 加载；仅后端 run_server.py 读取，前端代理不跟随）
BACKEND_HOST=0.0.0.0
BACKEND_PORT=9000
```

> 前端 dev 端口 8080 目前在 `vite.config.ts` 中固定，暂不随 `BACKEND_PORT` 变化。

## 静态检查与 CI

本地门禁（与 CI 等价）：

```bash
make ci
```

分项：

```bash
# 后端（pytest 含覆盖率门禁：app 整体 ≥80%）
python -m ruff check backend/app        # 风格/告警
python -m mypy backend/app              # 类型检查（strict）
PYTHONPATH=backend python -m pytest tests/ --ignore=tests/integration --ignore=tests/e2e -q --cov=app --cov-fail-under=80

# 前端（vitest 覆盖率为分层门禁：services/stores 语句/行 ≥80%，
#       VideoPlayer / LogcatView / DebugPanel ≥70%）
cd frontend && npm run lint && npx vitest run --coverage && npm run build
```

CI 配置见 `.github/workflows/ci.yml`：push / PR 到 `master` 触发，ubuntu-latest 上跑
后端 ruff+mypy+pytest、前端 eslint+vitest+build。**E2E 不进 CI**（见下）。

## 端到端测试（E2E，本地）

E2E 需要**物理 Android 设备**，托管 CI runner 无设备，故仅在本地运行：

```bash
# 仓库根，自动拉起后端(8765)+前端(8080)，以 APP_ENV=e2e 关闭自适应码率
npm run test:e2e

# 多设备环境下钉住测试设备（默认取第一个 online 设备）
E2E_DEVICE=192.168.8.22:5555 npm run test:e2e
```

约定与已知设备限制见 [`tests/e2e/README.md`](../tests/e2e/README.md)。要点：
`workers=1` 串行、仅 Chrome(chromium)、设备类用例无在线设备时自动 skip。

## Docker（开发参考，未验证）

`docker/`、`docker-compose.yml` 保留为服务器化方向的骨架，但**未在 Linux 容器实测**：
后端依赖的 ConPTY/pywinpty、scrcpy.exe、ProactorEventLoop 均为 Windows 专属，Linux
容器内预期无法完整工作。请勿将其作为发布产物；相关命令（`make docker-up` /
`make docker-down`）标注为可选，仅供方向探索。

## 已知限制

- 运行平台：仅 Windows 实测；Linux/macOS 未验证。
- mypy strict：覆盖 `backend/app` 全部 56 个源文件；`backend/app/scrcpy/examples.py`
  为示例脚本，纳入类型检查但非运行期依赖。
- E2E：不进 CI，依赖真机；部分 ROM（如 RK3288）存在编码器/旋转差异，相关用例自动
  skip 或同时接受 h264/screenshot 模式。
- 自适应码率重启会在切档瞬间产生 1–3s 黑屏（前端 watchdog 已做回退处理）。
