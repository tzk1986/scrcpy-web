## 发现清单（一）：代码审查 — 通过（0 阻塞 / 3 建议 / 11 观察）

### 建议（3 条，本批全部修复）

1. **空/缺失 YAML 被当作合法配置静默回落内置默认值**（`config_watch.py` × `config/settings.py`）。
   探针实测：清空/删除 base.yaml 后 `reload_config()` 报告成功，配置被整体替换为内置默认值
   （`min_log_level` V→I、`log_rate_limit` 500→100、`max_db_size_mb` 2048→1000），
   与「重载失败保留旧配置」的宣称不符；`max_db_size_mb` 降低还可能波及下一轮日志裁剪。
   **处置**：`reload_settings()` 对 `base.yaml` 缺失/为空抛 `ValueError`（失败路径，保留旧配置 +
   告警），新增 2 例测试（`reload_config` 直调与 HTTP 端点 400）。
2. **外层 `aclose` 不级联关闭内层 `shell.execute()` 生成器**。探针实测：会话锁同 tick 释放 ✓，
   但内层生成器靠 asyncgen finalizer 约 50ms 后才收尾，期间 `_executing` 为 True、内层锁被持有。
   **处置**：内层补 `async with aclosing(shell.execute(cmd))`；`ShellSession.execute` 与
   `InteractiveShell.execute` 返回类型由 `AsyncIterator[str]` 精确为 `AsyncGenerator[str, None]`
   （根治 mypy 无法通过 `aclosing` 的问题）；新增 `test_stream_raw_closes_inner_generator_on_consumer_close`。
3. **WS exec 断开路径二次 send 导致 RuntimeError 逃逸，绕过清理**。探针复刻 Starlette 语义实测：
   订阅者残留 `{'s1': 1}`、转发任务残留 `['s1']`，且「全部订阅者断开 → 宽限后停采」判定不触发。
   **处置**：exec 分支改 `except WebSocketDisconnect: raise` + `_safe_send_json` 兜底回发；
   `unsubscribe`/`stop_output_forwarding` 收进 `finally`（覆盖所有退出路径）；新增
   `tests/unit/test_ws_debug.py` 4 例（断开中、命令错误+回发失败、非法消息、正常断开）。

## 发现清单（二）：方案 18 设计审查 — 打回（4 阻塞 / 14 建议 / 7 观察）

核心判定：需求「暂存数据在执行完成后清除」的三个触发点中，**设备离线/空闲停采**
与**服务关闭**在 v1.0 设计下都不会清除暂存（`_sampling_loop` finally 不 pop `_buffers`、
lifecycle 从不调用 `performance_service.cleanup()`）；清理循环无异常隔离，
叠加新引入的 VACUUM 后可被一次 `database is locked` 永久击穿；录制状态机未定义，
「开录制后切走页面」会静默丢数据。

### 阻塞（4 条，已全部补进方案 v1.1）

- **B1** 离线/空闲停采不释放暂存，且 Network 侧无失联信号（`NetworkSampler` 全异常吞没）→
  方案补：`_sampling_loop` finally 统一走 `_release_device`（含 buffer pop）；
  空闲停采走 `stop_monitoring` 而非 `sample()` 自然结束路径；`get_stats(strict=True)` 失联判定；
  验收补「停止/离线后缓冲为空」断言。
- **B2** 「服务关闭」触发点不存在（`cleanup()` 是死代码）→ 方案补 §3.7：lifecycle 关闭段新增
  `performance_service.cleanup()` / `network_service.cleanup()`（含录制 final flush）、
  `deps.py` 注册 NetworkService、交付物补齐。
- **B3** 录制状态机未定义 → 方案补 §3.6 状态机表（11 个事件 × 处理），覆盖空闲停采与录制冲突、
  离线/重连、总开关热重载、`RECORDING_DISABLED` 400、重启后语义。
- **B4** 清理循环无异常隔离 → 方案补 §3.8：`run_cleanup()` 分段 try/except + 外层续跑 +
  结构化告警；风险表改写（WAL 不豁免 VACUUM 独占要求）。
