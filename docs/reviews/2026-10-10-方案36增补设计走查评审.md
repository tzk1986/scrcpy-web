## A. D7 缩略图自动加载 — ⚠️

### A1 watch 机制可靠性 — ✅

- pinia setup store 内注册 `watch` 可靠。pinia 2.3.1（node_modules 实装版）对 setup store 以 `effectScope` 包裹 store setup 函数，`watch` 只需 effect scope、不依赖组件实例；无 app 上下文的 `setActivePinia(createPinia())`（`frontend/src/stores/device.test.ts:73`、`Dashboard.test.ts:191-192`）场景下 watcher 正常注册并随 nextTick 队列冲刷。测试侧 `flushPromises()`/`vi.waitFor` 即可断言。
- 三类变异均能触发关键串变化：SSE push（`device.ts:212` `devices.value.push`）、fetchDevices 整体替换（`device.ts:97` `devices.value = list`）、SSE 断开 filter（`device.ts:216` 新数组引用）。
- 关键串 `id:status` 的取值域核实：后端产出设备 status 恒为 `"online"`（`cli.py:203` get_device_info 固定 `status="online"`；`device_service.py:180-187` _fallback_device 同为 `"online"`；`domain/device.py:40` 注释允许 `online|offline|busy` 但当前链路只写 online）。**D7 的 `status==='online'` 过滤实际等于「全部设备」，不会漏触发**。✅
- 无环路：loadThumbnail 只改 thumbnails/thumbLoading/thumbFailed 三态（`device.ts:295-336`），不触 devices；fetchDevices 的差集清理（`device.ts:100-108`）只清三态不清 devices。

### A2 与既有 thumbCancelled/reconcile 的相互作用 — ✅

- reconcile 在 `devices.value = list` 之后同步执行（`device.ts:97-108`），D7 watcher（flush pre）运行于其后——cb 时差集清理已完成，不会对已消失设备发起加载。
- thumbCancelled 只影响「移除后不回写」（`device.ts:314-319`），与 watcher 无交集；重新出现设备的 loadThumbnail 会 `thumbCancelled.delete`（`device.ts:302`）恢复写入资格。
- `scanSubnet` 既有显式 `loadThumbnails(okIds)`（`device.ts:182`）与 D7 watcher 会在扫描后重叠触发：TTL 命中（`device.ts:299-301`）或 in-flight 合并（`device.ts:296-297`）吸收重复，不会重复 screencap。✅

### A3 失败不自动重试是否遗漏自愈路径 — ⚠️（可接受，建议补一行论证）

- 「短暂离线又恢复」自愈路径**存在**：设备断开→SSE disconnected 移除行 + `removeThumbnail` 连带清 thumbFailed（`device.ts:216-217`、`device.ts:255-264`）→ 恢复后 SSE connected 重新 push（status 恒 online）→ 关键串变化 → 自动加载重试。即「失败→移除→重入」会被 watch 自动重试，「失败→原地停留」不重试——后者恰是防重试风暴的设计目标，边界成立。
- 唯一不自愈的残留边：设备**不离开列表**仅状态翻转（如 busy→online，当前后端不产生此形态）或 SSE 未接线场景下设备离线期间列表未刷新——此时 thumbFailed 保留，需手动「点击重试/刷新缩略图」。API.md:255 已注明生产 SSE 事件流「当前未接线启动」，前端兜底靠操作后重拉与手动刷新，故自愈依赖 refetch 路径（任意一次 fetchDevices 令设备消失再出现即关键串变化→自动重试）。
- 修订建议：定稿补一句「thumbFailed 由设备移除路径（removeThumbnail）连带清理，重入列表即获一次自动重试」，评审即可闭环；不需要额外定期重试机制。

### A4 「点击加载」占位保留 — ✅ 保留

### D2 无 row-key 时数据变化后的选中残留 — ⚠️ 语义需写进设计

EP 2.14.5 `setData`（store/index.mjs:27-41）实际行为：

- **整体换数组（fetchDevices `devices.value = list`、SSE 断开 filter）→ 自动 `clearSelection()` 并 emit `selection-change []`**——即每次列表重拉/断开事件都会把用户刚选中的设备清空，工具条会中途消失。批量断开成功后本地 filter 移除也自带清选（隐式满足「执行后清空选中」）。
- **同引用 push（SSE connected）→ `cleanSelection()`**，已选行保留、消失行剔除（watcher.mjs:227-247）。
- 推断：若批量断开**全部失败**（不产生本地移除），选中不会自动清——设计的「执行后清空选中」需**显式**执行（table ref `clearSelection()` 或清空选中状态 ref），不能靠隐式行为。
- 修订建议：定稿写明「选中态由 @selection-change 驱动的 `selectedIds` ref 承载；批量断开收尾显式清空；列表重拉/SSE 断开引起的隐式清空属预期行为（不设 row-key、不用 reserve-selection）」。否则实施者会与「选中莫名消失」的测试结果纠缠。

### E2 区间解析边界 — ✅ 全部可解，注意三个实现坑

- 判定顺序安全：含 `/` 走 CIDR（`ip_network` 自然拒绝 `10-100/24` 混写）；否则含 `-` 且 `split('-')` 恰 2 段走区间；否则走单 IP/CIDR 兜底（`ip_network(x, strict=False)` 天然把裸 IP 归一为 /32，现有行为不变，`devices.py:254-262` 佐证）。
- 完整端点写法：`ip_address()` 在 py3.9.5+ 拒绝前导零八位组（项目 requires-python >=3.10，pyproject.toml:7），前导零 IP 天然非法 ✅；但**简写右端必须显式字符串校验**（`int("010")` 会静默通过成 10）。
- 其他边界收口：空右端（`…10-`）→ 拆分第二段空串先拒；多 `-` → 段数 != 2 拒；倒序 → `end_int >= start_int` 判；>255/负值 → 校验后拒；`10 - 20` 带空格 → 建议严格拒绝（设计未提，实施时或 trim 或拒，须定稿二选一，防「strip 容忍」与「前导零严格」口径不一致）。
- **排序不变式**：区间展开必须从 start 递增迭代（IPv4Address int 自增），保持 reachability「数值序」契约——现有测试以 IP 数值序断言开放主机顺序（test_reachability.py:107），实施为 reverse/dedup 顺序会挂。
