## 发现清单

### 高危

**H1 ConPTY 交互式 shell 通道宿主命令注入（预核事实 #1 全局结论被推翻）**

- 位置：`backend/app/infrastructure/adb/winpty.py:182-183`：
  ```python
  inner = subprocess.list2cmdline([command] + argv[1:])
  cmdline = f' /Q /C "chcp 65001>nul & {inner}"'
  ```
  device_id 经 `infrastructure/adb/shell.py:143` 进入 argv（`(adb_path, "-s", device_id, "shell", "-tt")`），最终到达 `winpty.py:189` 的 `pty.spawn(comspec, cmdline=cmdline)`；device_id 源头为 `interfaces/http/debug.py:35-56` 的 query 参数原样透传（存于 `debug_service.py:116-122` 的 session.device_id）。
- 机理：`subprocess.list2cmdline` 仅在参数含空格/引号时加引号；仅含 cmd 元字符（`&`、`|`、`^`、`%` 等）而无空白的参数不会被包裹 → cmd.exe 将 `&` 视为命令分隔符，把注入片段作为**独立宿主命令**执行。
- 复现路径：`POST /api/debug/sessions?device_id=127.0.0.1%26whoami&user_id=u` → 获得 session_id（可预测，见 H2）→ 连 `WS /ws/debug/{session_id}` 发 `{"op":"subscribe"}` → `get_or_create_shell` → Windows ConPTY 分支 `spawn_conpty` → 注入命令以宿主进程用户身份执行。
- 验证：以与 `spawn_conpty` 相同的 cmdline 构造在本机子进程仿真复现（`[comspec, "/Q", "/C", cmdline]`），注入的 `echo`/`whoami` 片段均作为独立宿主命令执行；未对运行中服务实测。
- 影响范围：Windows + pywinpty（`pyproject.toml:14` 硬依赖、打包内嵌，ConPTY 为 Windows 活动路径）；非 Windows 管道回退（`shell.py:154-160`）走列表参数无此问题。结合 H2+H3 构成**跨站全链 RCE**（无需本机凭据）。
- 修复建议：**超出 A2-A4 预判，建议立新任务 TDD 修复（控制器裁决）**。方向：① ConPTY 通道禁止字符串拼接——自定义 cmd 引用函数对 `& | ^ < > % ! "` 全量转义，或改为经 stdin 注入命令；② device_id 在 create_session 层做 ADB serial 字符集白名单校验（上游截断）。

**H2 会话 ID 生成非 uuid4 → 可预测性（喂养 H1/H3 链）+ 导出文件名注入面（预核事实 #2 例外）**

- 位置：`backend/app/application/debug_service.py:116` `session_id = f"{device_id}_{user_id}_{int(time.time())}"`；`device_id`/`user_id` 为 `interfaces/http/debug.py:35-56` query 参数原样透传，随后未经净化进入 `interfaces/http/debug.py:154/158` `filename = f"logs_{session_id}.csv|.json"` 与 `163` 的 `Content-Disposition: attachment; filename="{filename}"`。
- 影响面：
  1. **导出文件名注入面**：session_id 含 `"` 可打断文件名引号（下游文件命名歧义）；含 CRLF 时 h11 拒绝非法头值 → 响应发送失败、连接中止（协议层兜住，无响应头拆分）。同族对照：`network.py:166`/`performance.py:187` 仅 `replace(":", "_")`，device_id 路径参数同为用户输入。
  2. **可预测性**：`int(time.time())` 秒级时间戳——攻击者在创建会话后于 ±秒级窗口穷举即得 session_id，为 H1/H3 的跨站利用链提供「可知会话」前提（也放大 session spam 面，见 L2）。
- 复现：`POST /api/debug/sessions?device_id=x%22y&user_id=u` → 导出 CSV → 观察 `Content-Disposition` 文件名。
- 修复建议：A3 的 `sanitize_export_filename` 覆盖三导出端点（含 debug session_id 语境）；根因侧建议 session_id 改 `uuid4().hex` 或对 device_id/user_id 上游白名单——session_id 兼作查找键与持久化键，改动面已超 A3 计划，**根因修复由控制器裁决**。

**H3 WS 跨站不设防 + A2 修复方案设计缺口**

- 位置：`backend/app/main.py:127-140` 三个 WS 端点无任何 Origin/鉴权校验；CORS 中间件（95-104）不约束 WS（浏览器 WS 不受 CORS 保护，仅靠服务端校验 Origin）。
- 影响：任意网页可跨站连 `ws://127.0.0.1:8765/ws/debug/{session_id}`（H2 使 session_id 可知）后发 `exec`/`subscribe`；`interfaces/ws/performance.py:65` 连接即 `stream_metrics` 自动启动设备监控；`interfaces/ws/video.py:115-129` 可注入输入事件。三条链均无跨站门槛。
- 复现路径：非同源页面执行 `new WebSocket("ws://127.0.0.1:8765/ws/debug/{session_id}")`（session_id 经 H2 可知）发 `{"op":"exec",...}` → 无 Origin 校验直接执行（`main.py:127-140` 无守卫；`ws/debug.py:126`）。
- 修复方案指正（对 A2 实施计划的直接输入）：A2 拟以 `BaseHTTPMiddleware` 实现 origin_guard 并宣称「对 WS 握手同样检查」——**不成立**（核验 starlette 1.3.1（系统 Python）/ 1.7.0（build/venv）源码，机制相同：非 http scope 直接透传）。A2 需改为 ASGI 原生中间件（包裹 http+websocket 两型 scope 分派）或 WS 端点内取 `websocket.headers["origin"]` 校验，否则 H3 不解决。另注：`netloc == Host` 形式的同源比较对 DNS rebinding 的覆盖有缝隙——攻击页面与目标服务端口相同时（如页面 `http://evil.com:8765` 重绑到 127.0.0.1:8765），Origin 与 Host 同为 `evil.com:8765`，比较通过；健壮做法是 Host 头回环名白名单（`localhost`/`127.0.0.1`/`::1`）。建议 A2 将「Host 非回环名应拒绝」列入测试用例。
- 修复建议：归 **A2**（修正设计后覆盖 WS 握手），no-Origin 策略（非浏览器客户端）由 A2 明示。

### 中危

**M1 源码 dev / docker 模式绑定 0.0.0.0 且零鉴权（超出 spec「本地回环」前提）**

- 位置：`run_server.py:83` dev 分支 `_serve(app, srv.host, srv.port)`；`config/base.yaml:10-11` `host: 0.0.0.0`；`config/settings.py:30` 默认同；`docker/Dockerfile.backend` CMD `--host 0.0.0.0`；测试锁定该值（`tests/unit/test_config_port.py:28` 断言 `== "0.0.0.0"`）。
- 影响：开发模式下局域网任意主机可直达全部 API（结合 H1 即局域网 RCE）。冻结打包（exe）路径 `core/launcher.py:164-171 resolve_bind_host` 强制 127.0.0.1，安全——spec §A1 的「本地回环」前提只对 frozen 成立。方案 23/36 文档已记录该 0.0.0.0 为遗留项。
- 复现路径：dev 起服务（`run_server.py:83`，host 0.0.0.0 见 `config/base.yaml:10-11`）→ 局域网任意主机 `curl http://<开发机IP>:8765/api/devices` 无凭据得 200。
- 修复建议：**超出预判，控制器裁决**。dev 默认回环、局域网调试须显式环境变量开启（改动触碰上述测试断言）或方案文档明示风险。

**M2 WS 消息健壮性缺口（超出 A4 计划覆盖面的部分）**

- 位置：`interfaces/ws/debug.py:84` `receive_json()` 未捕获非 JSON/非 dict 输入（异常走 finally 清理后连接异常关闭——starlette 以 1011 close，无栈泄露到客户端，但属未受控断开）；`92-93` `int(from_seq)` 非法值 ValueError 未捕获；`112-115` filter 的 level/tag/paused 无类型校验直入 `set_subscriber_filter`；`126` `command` 无类型校验直入 exec 链；`147-153/168-172/190-194` 异常 `str(e)` 直发客户端（内部错误文本泄露，非栈）；`interfaces/ws/performance.py:84` 错误路径 `close(str(e))` 将异常文本置入关闭原因（同型泄露）。
- 复现路径：连 `WS /ws/debug/{session_id}` 发非 JSON 文本帧 → `receive_json` 未捕获异常、1011 未受控断开（`ws/debug.py:84`）；发 `from_seq` 非法值（如 `"abc"`）→ ValueError（`92-93`）。
- 修复建议：归 **A4（parse_ws_message）**——实施时须将上列「解析后校验」纳入：非法 JSON → error 回执不断连；from_seq/字段类型校验；error 文本脱敏。若 A4 只做 JSON 层解析，本项残留（实施者对照本清单核对）。

**M3 apps 族 package 参数直插设备侧 shell 字符串**

- 位置：`application/app_service.py:275/342/375/411/438/458/484`（`dumpsys package {package}`、`pm list packages -f {package}`、`dumpsys meminfo {package}`、`monkey -p {package}`、`am force-stop {package}`、`pm uninstall {package}`、`pm clear {package}`）；package 来自 `interfaces/http/apps.py:102-107/126-131/150-155/174-179/198` 路径参数，无格式校验。
- 影响：命令落到**设备端** shell（adb `shell` 单参数字符串语义），注入能力与既有 exec_shell 端点等同（不构成权限升级、不触宿主）；但可把破坏性动作串接扩权（如 `com.a; pm uninstall com.b`）。
- 修复建议：package 名正则白名单（`^[A-Za-z0-9._]+$`）；**中低危排队**，建议并入后续批次（可附属 A3 同批做输入校验）。

### 低危

- **L1 SSE 资源面**：`interfaces/http/devices.py:71-140` 每连接独立 Queue 无上限、连接数无上限、回调注册/移除走私有列表（127-130）；停机优雅收尾已做（116-124）。建议：连接/队列上限或订阅复用。复现路径：循环 N 路 `GET /api/devices/events` 长连 → 连接数与队列随 N 线性增长无上限。
- **L2 会话面无配额/可预测 ID**：`interfaces/http/debug.py` create + `debug_service.create_session` 可无限创建（键含秒级时间戳不覆盖）；协作会话同型未校验拼接 `application/session_service.py:58` `f"{device_id}_{user_id}"`（无时间戳、更可预测，仅内存面）。建议：上限/过期清理与格式白名单（顺带收窄 H2 穷举窗口面）。复现路径：循环 `POST /api/debug/sessions?device_id=dev1&user_id=u` → 会话数无上限；协作会话 ID 按 `f"{device_id}_{user_id}"` 直接枚举（`session_service.py:58`）。
- **L3 帧断开解析 500**：`interfaces/http/devices.py:373-377` `int(parts[1])` 对非数字段 ValueError → 500（应 400 校验）。复现路径：向帧断开路径传非数字段 → `int(parts[1])` ValueError → 500。
- **L4 错误消息反射**：`core/exceptions.py:66/75/124/134` 用户输入回显进异常消息；兜底处理器 178-188 已对未预取异常脱敏（无栈泄露）。复现路径：发送触发校验失败的请求（如非法字段值）→ 响应异常消息原样回显输入。
- **L5 /docs + /openapi.json 默认暴露**：无鉴权环境下的接口信息面（debug 模式 schema 更丰富）。可随 A2 一并收敛（生产禁用）。复现路径：浏览器直访 `http://127.0.0.1:8765/docs` 与 `/openapi.json` → 无凭据可读全量接口 schema。
- **L6 install_apk 宿主任意路径**：`interfaces/http/devices.py` batch_install/install 读宿主 apk_path——本地工具语义（用户自选文件），记录备查。复现路径：install/batch_install 传任意宿主 apk_path → 服务端读取该路径文件。
- **L7 接口层访问私有成员（架构注记）**：`interfaces/http/devices.py:127-130`（`service._on_device_connected`）、`interfaces/ws/debug.py:129`（`debug_service._exec_shell_stream_raw`）——非安全漏洞，四层约束注记。复现路径：静态走查即证（上列两处调用点）。
- **L8 死代码**：`application/debug_service.py:695` `exec_shell_stream` 无调用方（被 `_exec_shell_stream_raw` 取代），建议清理。复现路径：全仓 grep `exec_shell_stream` 调用方 → 0 处（仅定义与 `_raw` 变体）。

## 已核查无问题项（备查）

- `cli.py` 命令式通道全列表参数（97/101-106/128-144/287-298），无宿主拼接；`shell*` 的 cmd 单参数进**远端** shell 属功能本体（`cli.py:21-24` docstring 已注明安全模型）。
- `infrastructure/adb/shell.py:143,154-160` 管道回退 `create_subprocess_exec` 列表参数无事；ConPTY argv 构造本身无事——缺陷在 `winpty.py:182-183` 拼接（H1）。
- `sqlite.py` 全参数化：`?` 占位覆盖用户数据；f-string 仅硬编码表/列名（504-527/775-787/822-825/845-847/887-947）。
- `main.py:158-170` SPA fallback 路径 containment：`resolve()` 先于 `stat` + `is_relative_to(root)`（167-168），`api`/`ws` 首段保持 404（162-163）——无穿越/逃逸。
- `interfaces/ws/video.py:128-129` 输入消息 broad except 吞（鲁棒性达标、无信息泄露）。
- `interfaces/http/devices.py:271-333`（扫描目标解析）与 336-355（connect）可令服务端连任意 host:port——扫描/连接系功能本体，记录备查。
- `deps.py`/`lifecycle.py` 无鉴权依赖属公开设计（本地工具），本报告按 spec 前提处理，未列为独立发现。

## 结论

攻击表面审查完成。**高危 3 / 中危 3 / 低危 8**；预核事实 6 项中：4 项确认，#1 全局结论被推翻（ConPTY 例外，H1）、#2 出现 uuid4 例外（H2——按 brief 定格高危）、#6（A2 设计）被推翻（H3 载明修正方向）。总体修复路径：A2 修正设计后并入执行（覆盖 HTTP+WS 双 scope）、A3 净化扩至 debug 会话语境、A4 解析+校验补面；**H1 宿主注入为最高优先，须立新任务先行修复**。H2 根因（session_id 生成）与 M1（dev 监听）由控制器裁决归属。
