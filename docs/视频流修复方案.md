# 视频流修复方案

> 日期：2026-09-09
> 状态：**已更新**（根据 scrcpy 官方源码修正）
> 优先级：高
> 版本：v2.0（修正 scid 格式为十六进制）

---

## 1. 问题描述

当前视频流功能无法正常工作。启动 scrcpy-server 后，Python 端通过 `adb forward` + socket 连接后，收到 0 字节数据。录制文件只有 48 字节（仅含文件头）。

---

## 2. 根因分析

### 2.1 核心问题

**scrcpy-server.jar v4.1 的参数格式与代码假设不匹配。**

| 项目 | 代码假设（错误） | 实际情况（官方源码） |
|------|----------------|-------------------|
| scid 格式 | 十进制字符串（如 `"12345678"`） | **十六进制**（如 `"39a6de02"`，`%08x` 格式） |
| socket 名称 | 固定 `"scrcpy"` | `scrcpy_<scid>`（如 `"scrcpy_39a6de02"`） |
| `tunnel_forward` 参数 | 不被识别或无效 | **有效**！切换 server 的 listen/connect 模式 |
| Python 端角色 | TCP client（主动连接） | TCP server（监听，等待 server 连接） |

**根本原因**：
1. scid 格式错误导致 server 解析失败
2. socket 名称不匹配导致连接失败
3. Python 端用 `open_connection`（客户端）而不是 `start_server`（服务端）

### 2.2 证据链

1. **logcat 堆栈跟踪**（关键证据）：
   ```

       at android.net.LocalSocketImpl.connectLocal(Native Method)
       at android.net.LocalSocketImpl.connect(LocalSocketImpl.java:292)
       at android.net.LocalSocket.connect(LocalSocket.java:131)
   ```

   - `LocalSocket.connect()` 是**客户端**操作（连接远端）
   - `DesktopConnection.connect()` 表明 server 在尝试连接到桌面端
   - 如果是服务端模式，应该看到 `LocalServerSocket.accept()`

2. **参数解析错误**：
   - `tunnel_forward`（无值）→ `Invalid key=value pair: "tunnel_forward"`
   - `--tunnel-forward` → `Invalid key=value pair: "--tunnel-forward"`
   - 说明 v4.1 版本的参数格式与预期不同

3. **socket 命名**：
   - 设备上的 socket 名称为 `@scrcpy_<scid>`（如 `@scrcpy_39a6de02`）
   - **scid 格式为 8 位十六进制零填充**（`%08x`）
   - 当前代码使用固定名称 `scrcpy`，不匹配

## 3. 修复方案

### 3.1 架构变更

```
修改前（错误）：
  Python (TCP client) → adb forward tcp:PORT localabstract:scrcpy
                         → device → scrcpy-server (应等待连接，但实际尝试反向连接)
                         根因：socket 名称不匹配 + scid 格式错误

修改后（正确）：
  Python (TCP client) → adb forward tcp:PORT localabstract:scrcpy_<scid_hex>
                         → device → scrcpy-server (tunnel_forward=true, 等待连接)
```

**关键理解**：
- `tunnel_forward=true`：scrcpy-server 在设备端作为服务端（LocalServerSocket），等待客户端连接
- `adb forward`：将 Python 端的 TCP 端口 转发到 设备上的 abstract socket
- Python 连接 `127.0.0.1:PORT` → adb 隧道 → 设备端 server 接受连接
- **scid 必须是十六进制**：`%08x` 格式（如 `39a6de02`），与设备端 socket 名对应
- **socket 名必须含 scid**：`scrcpy_<scid_hex>`，否则 server 监听与 adb 转发对不上

### 3.2 新连接流程

```
┌──────────────┐         ┌──────────────┐         ┌──────────────┐
│   Python     │         │   ADB Host   │         │   Device     │
│              │         │              │         │              │
│              │         │              │         │ 1.启动server │
│              │         │              │         │ (tunnel_forward=true)
│              │         │              │         │ 监听 scrcpy_ │
│              │         │              │         │ <scid_hex>   │
│              │         │ 2.adb forward│         │              │
│              │         │ tcp:PORT ────┼─────────► localabstract│
│              │         │              │         │ :scrcpy_XXXX │
│ 3.connect()  │         │              │         │              │
│ 127.0.0.1:   │─────────┼──────────────┼─────────► 4.accept()   │
│ PORT         │         │              │         │ 连接建立     │
│ 5.读取H.264  │◄────────┼──────────────┼─────────┤ 6.发送视频流 │
└──────────────┘         └──────────────┘         └──────────────┘
```

### 3.3 详细实施步骤

#### 步骤 1：修改 scid 和 socket 名称（关键修复）

```python
import secrets

# 生成 31 位随机数并格式化为 8 位十六进制（小写，零填充）
scid_num = secrets.randbelow(2**31)  # 31 位随机数
scid_hex = f"{scid_num:08x}"          # 8 位十六进制，如 "39a6de02"
socket_name = f"scrcpy_{scid_hex}"    # socket 名称，如 "scrcpy_39a6de02"
```

**为什么是十六进制？**
- scrcpy C 客户端用 `%08x` 格式化（printf 的十六进制）
- scrcpy Java 服务端用 `Integer.parseInt(value, 0x10)` 解析（基数 16）
- 官方示例：`scid=39a6de02`（见 [doc/develop.md](https://github.com/Genymobile/scrcpy/blob/master/doc/develop.md)）

#### 步骤 2：启动 TCP 监听器

```python
import asyncio

async def start_listener(port: int) -> tuple[asyncio.StreamReader, asyncio.StreamWriter]:
    """启动 TCP 监听器，等待 server 连接。"""
    connected_event = asyncio.Event()
    result = {}

    async def handle_client(reader, writer):
        result['reader'] = reader
        result['writer'] = writer
        connected_event.set()

    server = await asyncio.start_server(handle_client, '127.0.0.1', port)
    
    try:
        await asyncio.wait_for(connected_event.wait(), timeout=10.0)
    except asyncio.TimeoutError:
        server.close()
        await server.wait_closed()
        raise RuntimeError("Timeout waiting for scrcpy-server connection")
    
    # 关闭监听器（只需要一个连接）
    server.close()
    await server.wait_closed()
    
    return result['reader'], result['writer']
```

## 4. 已知风险

### 4.1 tunnel_forward 参数可能不被识别

**现象**：之前测试时出现 `Invalid key=value pair: "tunnel_forward=true"` 错误。

**可能原因**：
1. 参数格式错误（应该用 snake_case，不是 kebab-case）
2. 参数位置错误（必须在 version 之后）
3. scid 格式错误导致 server 解析失败，间接影响其他参数

**缓解措施**：
- 严格按照官方示例格式：`scid=<8位hex> tunnel_forward=true`
- 使用十六进制 scid（这是最可能的根因）
- 添加详细的 logcat 日志收集，便于诊断

### 4.2 adb forward 在 WiFi 连接设备上可能失败

**现象**：`adb forward` 报 `more than one devices/emulator` 错误。

**原因分析**：
- 当前设备通过 WiFi 连接（`192.168.8.34:5555`）
- 系统中可能存在多个 adb 连接

**缓解措施**：
1. 确保只用 `-s <device_id>` 指定设备
2. 如果失败，尝试 USB 连接
3. 检查 `adb devices` 输出，确保只有一个设备

### 4.3 scrcpy-server 版本兼容性

当前 JAR（733KB，git revision `fa57d7c6`）与预期的 v2.4 行为差异很大。

**关键发现**：
- v4.1 使用 `%08x`（十六进制）格式化 scid
- v2.4 可能使用不同的参数格式

**建议**：
- 优先使用当前的 v4.1 JAR
- 如果失败，考虑下载 scrcpy v2.4 的 server JAR

### 方案 B：使用 screenrecord 替代

```python
# 使用 Android 内置 screenrecord 命令
cmd = [
    "adb", "-s", device_id, "shell",
    "screenrecord",
    "--output-format=h264",
    "--size", f"{opts.max_size}x{opts.max_size}",
    "--bit-rate", str(bit_rate_value),
    "-",  # 输出到 stdout
]
# 从 stdout 读取 H.264 数据
```

**限制**：
- 不支持触控输入
- 帧率可能较低
- 需要 root 权限（某些设备）
